# PromERP — Импортонезависимая ERP-платформа для производства

[![Демо-стенд](https://img.shields.io/badge/Онлайн--демо-test.promerp.ru-007ACC?style=for-the-badge&logo=internet-explorer&logoColor=white)](https://test.promerp.ru/)
[![Документация](https://img.shields.io/badge/Документация-Интерактивная%20база-green?style=for-the-badge&logo=gitbook&logoColor=white)](https://test.promerp.ru/docs)
[![Стек](https://img.shields.io/badge/Технологии-100%25%20Open%20Source-success?style=for-the-badge)](#технологический-стек)

**PromERP** — российская модульная open-source ERP/MES-платформа для управления производством (приборостроение, машиностроение, металлообработка, сборка, позаказное и серийное производство).

Система спроектирована как полноценное, открытое и масштабируемое решение для отечественных предприятий, нацеленных на технологическую независимость, снижение санкционных рисков и отказ от дорогих проприетарных лицензий.

## Преимущества для российского бизнеса

### 🛡️ 100% Импортонезависимость и открытый стек
* **Нулевые санкционные риски:** Платформа построена исключительно на свободных технологиях с открытым исходным кодом (PostgreSQL, PHP 8.4, Linux). В ней отсутствуют скрытые зарубежные облачные зависимости, закрытые бинарные модули или лицензионные отчисления.
* **Кадровая доступность:** Разработка и сопровождение опираются на стек (PHP + PostgreSQL), специалистов по которому на российском рынке кратно больше, чем экспертов по закрытым зарубежным ERP (SAP, Oracle, MS Dynamics) или специализированным проприетарным языкам.
* **Защита инвестиций и отсутствие Vendor Lock-in:** Полный контроль над исходным кодом позволяет развивать и кастомизировать платформу как силами штатной команды предприятия, так и внешними подрядчиками.

### 🏭 Сквозной производственный контур
PromERP закрывает ключевые задачи предприятия без «лоскутной» автоматизации:
* **Инженерия и НСИ:** Версионируемые составы изделий (BOM), технологические карты, маршруты и параметры операций.
* **Планирование и обеспечение:** Балансировка мощностей, план-графики производства, материально-техническое снабжение (МТС) и WMS-склад.
* **Цеховой учет (Shop Floor / MES):** Диспетчеризация заказов, выдача сменно-суточных заданий, фиксация брака, контроль загрузки оборудования и рабочих центров.
* **Качество и прослеживаемость:** Контроль ОТК на всех переделах, рекламации, генеалогия партий изделий («от поставщика сырья до конечной отгрузки»).
* **Финансы и аналитика:** Расчет нормативной и фактической себестоимости (план/факт), производственный учет и BI-аналитика.

### 🔒 Безопасность и соответствие контурам
* **Локальный контур (On-Premise):** Платформа разворачивается на собственных мощностях предприятия или в доверенных российских ЦОД (Selectel, Yandex Cloud и др.), полностью изолируясь от внешней сети.
* **Аудит и контроль доступа:** Модуль сквозного аудита фиксирует историю любых изменений («кто, что и когда изменил»), что критично для служб безопасности и прохождения отраслевой сертификации.

### 🤖 Готовность к ИИ (AI-Ready via MCP)
* Встроенная поддержка протокола **MCP (Model Context Protocol)** позволяет подключать локальные или доверенные LLM-модели (агентов) для предиктивной аналитики, генерации отчетов, поиска сбоев в цепочках поставок и текстового взаимодействия с ERP.

## Технологический стек

Платформа принципиально избегает избыточных абстракций, сохраняя высокую производительность и простоту сопровождения.

| Слой | Технологии | Назначение в архитектуре |
| :--- | :--- | :--- |
| **СУБД** | **PostgreSQL 16** | Открытая СУБД; расширения: `ltree` (деревья/иерархии BOM), `btree_gist`, `pgcrypto`, `uuid-ossp`, `vector` (pgvector для AI-векторизации) |
| **Серверный язык** | **PHP 8.4** (совместимость с 8.1+) | Высокая производительность JIT, строгая типизация, предсказуемость |
| **Ядро фреймворка** | **Konine 3.4.0** («PHP84X») | Легковесный HMVC-каркас (Kohana-совместимый), расположен в `system/` |
| **Доступ к данным** | **Собственная ORM** + Driver | Оптимизированный модуль `orm` с прямым драйвером PostgreSQL без просадок по производительности |
| **CLI / Автоматизация**| **Minion** (`bin/console`) | Консольные утилиты: накат PostgreSQL-миграций, сборка НСИ, генерация модулей |
| **Интерфейс** | **Серверные View + Tailwind CSS** | Монолитный рендеринг без необходимости сложных фронтенд-сборок (Node.js не требуется в рантайме) |

## Архитектура системы

В основе системы заложен модульный принцип с четким разграничением ответственности:

```
[ HTTP-запрос / Веб-интерфейс ]      [ LLM-Агент (MCP) ]      [ Интеграции CSV/JSON / 1C ]
             │                               │                              │
             ▼                               ▼                              ▼
 ┌────────────────────────────────────────────────────────────────────────────────────────┐
 │                              Контроллеры (Controller_ErpNNN_*)                         │
 └───────────────────────────────────────────┬────────────────────────────────────────────┘
                                             │
                                             ▼
 ┌────────────────────────────────────────────────────────────────────────────────────────┐
 │                                Сервисы (Service_ErpNNN_*)                              │
 │            (Бизнес-логика, транзакции, события erp208, нотификации erp217)              │
 └───────────────────────────────────────────┬────────────────────────────────────────────┘
                                             │
                                             ▼
 ┌────────────────────────────────────────────────────────────────────────────────────────┐
 │                          Модели данных и ORM (Model_ErpNNN_*)                          │
 └───────────────────────────────────────────┬────────────────────────────────────────────┘
                                             │
                                             ▼
 ┌────────────────────────────────────────────────────────────────────────────────────────┐
 │                             База данных PostgreSQL 16                                  │
 └────────────────────────────────────────────────────────────────────────────────────────┘
```

**Фундаментальные правила платформы:**
1. Контроллеры тонкие — обращаются только к соответствующим сервисам.
2. Изоляция данных: модули не обращаются напрямую к таблицам других модулей; взаимодействие осуществляется только через вызовы сервисов или событийную шину (`erp208_events`).
3. Контроль схемы: любые изменения базы ведутся строго через версионируемые PostgreSQL-миграции (`migrations_pg/pgMigration_*.php`).

## Быстрый старт

### Требования к окружению
* **ОС:** Linux (Astra Linux, Alt Linux, Ubuntu, Debian, Rocky Linux и др.)
* **PHP:** 8.4 (допустимо от 8.1+) со стандартными расширениями (`pdo_pgsql`, `mbstring`, `json`)
* **СУБД:** PostgreSQL 16+

### Развёртывание проекта

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/starley1234/promerp.ru.git
   cd promerp
   ```

2. **Настройте конфигурацию подключения к БД:**
   ```bash
   cp application/config/database.sample.php application/config/database.php
   # Укажите параметры подключения к PostgreSQL в application/config/database.php
   ```

3. **Примените миграции базы данных:**
   ```bash
   ./bin/console pg:migrate
   ```

4. **Заполните демонстрационными данными (при необходимости):**
   ```bash
   ./bin/console demo:seed
   ```

5. **Запустите локальный сервер разработки:**
   ```bash
   php -S 0.0.0.0:8080 -t .
   ```
   После запуска интерфейс доступен по адресу `http://localhost:8080`.
