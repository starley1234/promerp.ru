# Компоненты интерфейса

Один набор разметки вместо копий в каждом модуле. Замер до появления этого
каталога (`docs/FRONTEND_REVIEW.md`): разметку карточки повторяли 290 файлов,
таблицу верстали руками 128 файлов, инлайн-обработчиков было 284, а
`aria`-атрибутов — 101 на все 358 представлений.

## Как пользоваться

```php
// короткая форма — строкой
echo Component::render('badge', array('label' => 'ниже минимума', 'state' => 'warn'));

// длинная форма — когда внутри есть разметка
Component::begin('card', array('title' => 'Остатки на складах', 'icon' => 'fas fa-boxes'));
?>
    ...любая разметка...
<?php
Component::end();
```

Хелпер — `application/classes/Component.php`, представления —
`application/views/components/*.php`.

**Живой эталон — `/pages/required_design_sample`.** Там же, в одном месте и без
входа: все компоненты с примерами вызовов и четыре собранные страницы — ввод
айтема, карточка айтема, перечень айтемов и сводная информация. Страница сама
собрана на этих компонентах; если пример на ней расходится с компонентом,
правильным считается компонент, а страницу правят в том же коммите.

## Правила

1. **Компонент — только вид.** Никаких запросов к базе и бизнес-логики: данные
   готовит контроллер или сервис.
2. **Текст экранируется внутри компонента** (`HTML::chars`). Готовый HTML
   передаётся только в переменных с суффиксом `_html` и только из кода проекта.
3. **У таблицы всегда есть подпись** (`caption`), заголовки со `scope`, а на
   узком экране — прокрутка: «на телефоне таблица обрезается» не должно
   повторяться.
4. **У цифры всегда есть подпись и единица измерения.** «7020» читается как
   угодно, «7 020 шт» — однозначно.
5. **Состояния — из одного словаря.** `ok`, `warn`, `bad`, `info`, `neutral` →
   цвет и слово берутся из `Component::states()`, а не подбираются на месте.
6. **Доступность по умолчанию:** доступное имя у кнопок-иконок (`aria-label`),
   декоративные иконки `aria-hidden`, у длинной таблицы — область прокрутки с
   именем, пустое состояние объясняет, что произошло.

7. **Режим интерфейса выбирает компонент, а не представление.** Простой/
   профессиональный режим (`Ui_Mode`) меняет, КАК компонент рисует данные;
   представление модуля `Ui_Mode::` не вызывает (проверяет `bin/frontend-audit.py`).
   См. раздел «Режимы интерфейса».

8. **Поля страницы задаёт шаблон, а не представление.** Отступы от бокового меню и
   верхней панели даёт `<main>` в `template_tailwindcss.php`. Корень представления —
   простой `<div>` (при необходимости `space-y-6` или `mx-auto max-w-3xl` для узкой
   формы), без `container`, `px-*` и `py-*`: иначе поля удваиваются, а на широком
   экране содержимое «уезжает» в центр с пустыми полосами по бокам. Эталон —
   `/traceability`. Проверяет `bin/frontend-audit.py`.

9. **На странице один `h1`.** Заголовок даёт `page_header`; если на странице
   показывают несколько шапок-примеров (эталон, сравнение видов), им передают
   `level => 2` и ниже — структура документа не ломается.

10. **Цель нажатия — не меньше 40 px.** Интерфейсом пользуются на планшете в цеху,
   часто в перчатках: поэтому кнопки, поля и ссылки листания несут `min-h-10`
   (40 px по высоте) при обычном `text-sm`. Мелкие ссылки-иконки допустимы только
   внутри строки таблицы и рядом с крупным действием.

11. **Шапка страницы — `page_header`.** Заголовок h1 (`text-2xl font-bold`), подпись,
   хлебные крошки и главные кнопки справа дают одним компонентом. Градиентные
   баннеры, `text-3xl`/`text-4xl`, `rounded-2xl`, палитры `slate`/`purple`/`indigo` в
   страницах не используются: акцент один — синий, нейтральные цвета — `gray`,
   панели — `card`, плитки — `rounded-lg border`. Так выглядят и рабочие страницы, и
   публичные (главная, о сервисе, документация, демо, условия, политика).

## Каталог

| Компонент | Переменные | Зачем |
| :--- | :--- | :--- |
| `page_header` | `title`, `lead`, `eyebrow`, `crumbs`, `meta`, `actions_html`, `level` | шапка страницы: h1 `text-2xl`, подпись, хлебные крошки, кнопки справа; одна на страницу. `level` (по умолчанию 1) снижает уровень заголовка, когда на одной странице показывают несколько шапок-примеров |
| `card` | `title`, `icon`, `subtitle`, `actions_html`, `body`, `id`, `flush`, `state` | панель страницы: один вид, заголовок с иконкой, кнопки в шапке |
| `kpi` | `label`, `value`, `unit`, `hint`, `target`, `state`, `url`, `trend`, `compact` | цифра с единицей, целью, состоянием и спарклайном |
| `badge` | `label`, `state`, `title` | состояние одним словом и одним цветом |
| `table` | `caption`, `columns`, `rows`, `row_header`, `row_class`, `empty_title`, `empty_hint`, `aria_label`, `sticky` | таблица: подпись, `scope`, прокрутка, приоритет колонок, пустое состояние |
| `empty` | `title`, `hint`, `action_html`, `icon` | «здесь пусто, потому что…» и что сделать |
| `pagination` | `page`, `pages`, `url`, `shown`, `total` | листание длинных списков |
| `filters` | `action`, `method`, `body`, `submit_label`, `reset_url`, `hidden` | единая панель отбора для списков |
| `toolbar` | `title`, `body`, `reset` | фильтры и действие «Применить» в одном доступном блоке |
| `form_field` | `id`, `name`, `label`, `type`, `value`, `hint`, `error`, `required`, `autocomplete` | поле формы с label, подсказкой и связью ошибки через ARIA; `autocomplete=off` по умолчанию для операционных данных, семантический токен задаётся явно для входа и контактов |
| `smart_reference` | `id`, `name`, `label`, `url`, `value`, `selected_label`, `placeholder`, `hint`, `required`, `min_chars` | интерактивно ищет сущность, показывает понятную подпись и отправляет скрытый ID; endpoint отвечает `{items:[{id,label,context}]}` |
| `tabs` | `tabs`, `label` | горизонтальные адаптивные вкладки с `aria-current` |
| `toast` | `message`, `type` | безопасное уведомление с `role="status"` |
| `more` | `summary`, `icon`, `open`, `plain`, `body` | «Ещё»: второстепенное, свёрнутое в простом режиме; в профессиональном содержимое идёт без обёртки |
| `mode_switch` | `class` | переключатель «Простой \| Профессиональный» (две ссылки на `/ui/mode/<режим>`) |
| `table_tiles` | как у `table` | вид `table` в простом режиме; сам не вызывается |

### Приоритет колонок

`columns[]['priority']`: `1` — видна всегда, `2` — скрывается до `sm`,
`3` — до `md`, `4` — до `lg`. Так на телефоне остаётся главное (номер, остаток,
состояние), а не первая попавшаяся колонка.

## Режимы интерфейса

Один продукт и один набор данных, два вида (`Ui_Mode`, `application/classes/Ui/Mode.php`):

- **простой** (по умолчанию) — те же данные «крупными клетками»: списки плитками,
  фильтры и второстепенные поля свёрнуты, меню без служебных разделов;
- **профессиональный** — прежний плотный вид: таблицы, все поля, все разделы.

Человек выбирает режим переключателем в боковом меню или в профиле; выбор помнит
браузер (cookie `ui_mode`) и учётная запись (`users_settings`).

Что делает каждый компонент в простом режиме:

| Компонент | Простой режим |
| :--- | :--- |
| `table` | плитка на строку: первая ячейка — заголовок, колонки `priority` 1–2 — «факты» (не больше четырёх), `priority` 3–4 и всё сверх четырёх — под «Подробнее», колонка «Действия» — кнопки внизу плитки |
| `kpi` | всегда крупная плитка (`compact` игнорируется) |
| `filters`, `toolbar` | свёрнуты в «Фильтры», раскрываются сами, если отбор уже задан |
| `more` | свёрнуто в «Дополнительные настройки» |

Как писать новый экран, чтобы он хорошо выглядел в обоих режимах:

1. Отдавайте данные компонентам (`table`, `kpi`, `filters`) и **не спрашивайте режим**.
2. В `table` ставьте `priority`: 1 — то, без чего строку не понять, 2 — важный
   факт, 3–4 — детали. Первая колонка — понятное имя строки (номер, название).
3. Второстепенные поля формы заворачивайте в `Component::begin('more')` … `end()`.
4. Для мелочей без PHP есть классы `pro-only` и `simple-only` (`assets/css/simple.css`).
5. Главное действие страницы — одно, остальные — в «Ещё» (`more`).

Режим — не защита: скрытое в простом режиме открывается по прямому адресу, права
решает ACL. Масштаб и мелочи простого режима — в `public_html/assets/css/simple.css`
(пишется руками, сборка Tailwind не нужна; все правила действуют только под
`html[data-ui="simple"]`).

## Проверки

`tests/Unit/ComponentsTest.php` описывает обещания компонентов: подпись и
`scope` у таблицы, прокрутка, экранирование (никакой HTML-инъекции через
данные), единица измерения у KPI, словарь состояний, спарклайн только по
числам. Правила, которые можно проверить статически, дублируются в
`dev:audit` — см. проверку «долг интерфейса».
