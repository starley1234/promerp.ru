# Перечень модулей (erp218_module_manager)

## Назначение
**Module Manager** — это централизованная система учета, инвентаризации и управления метаданными внутренних модулей ERP-системы на базе Kohana 3.3. 

В отличие от стандартного механизма подключения модулей, данный инструмент выполняет роль «паспорта» системы. Он позволяет отслеживать жизненный цикл каждого компонента в директории `application/modules/`, управлять их версиями, зависимостями и документацией, обеспечивая прозрачность разработки и упрощая аудит кода.

---

## Основной функционал

1.  **Сканирование и Регистрация:**
    *   Автоматическое обнаружение новых директорий в `application/modules/`.
    *   Парсинг метаданных из файлов `README.md` и конфигураций.
    *   Интеграция с **LLM (AI)** для автоматической генерации резюме функционала модуля.
2.  **Управление жизненным циклом:**
    *   **Версионность:** Поддержка стандарта SemVer (например, 1.2.4).
    *   **Статусы:** Отслеживание этапов (Alpha, Beta, Stable, Archived).
    *   **Публикация:** Управление видимостью модуля в системе через флаг `is_published`.
3.  **Контроль зависимостей:**
    *   Визуализация связей между модулями.
    *   Проверка наличия необходимых компонентов и минимально требуемых версий.
4.  **Документирование:**
    *   Ведение Changelog (истории изменений).
    *   Хранение технических заметок разработчика и инструкций по внедрению.

## API Модуля

Модуль предоставляет REST API для интеграции с внешними инструментами и дашбордами. Базовый URL: `/erp218_api/`

| Метод | Эндпоинт | Описание |
| :--- | :--- | :--- |
| `GET` | `/erp218_api/get_modules` | Получить список всех зарегистрированных модулей. |
| `GET` | `/erp218_api/get_stats` | Сводная статистика (кол-во активных, ошибки зависимостей). |
| `POST` | `/erp218_api/run_scan` | Запуск процесса сканирования директории модулей. |
| `PATCH` | `/erp218_api/update_status` | Обновление статуса или версии конкретного модуля. |

## Инструменты разработки: контекст модуля и документация

Модуль отвечает за то, чтобы разработчик или агент работал с одним модулем, не
читая весь репозиторий (см. `docs/AGENT_WORKFLOW.md`).

| Команда | Что делает |
| :--- | :--- |
| `bin/console module:context --module=erp401_wms` | Карточка модуля из кода: назначение, таблицы (свои и «чужие в SQL»), миграции, модели, сервисы с методами, контроллеры, роуты, права, события, MCP, зависимости, тесты и порядок чтения файлов. База данных не нужна. |
| `module:context --json` / `--list` / `--no-files` | Машинный формат, список модулей, карточка без порядка чтения. |
| `bin/console module:docs [--check] [--only=…]` | Обновляет сгенерированные блоки: таблицу модулей в `README.md` (`erp-modules`), инвентарь в `docs/ARCHITECTURE.md` (`module-inventory`) и `docs/MODULE_MAP.md`. `--check` возвращает код 1 при расхождении. |
| `make context module=erp401_wms` | Обёртка над `module:context`. |
| `make check-module module=erp401_wms` | Линт + аудит + дымовой прогон + тесты только этого модуля (~1 с). |
| `make docs` / `make docs-check` | Обновить/проверить сгенерированную документацию (входит в `make check`). |

Классы: `Service_Erp218_Context` (карточка), `Service_Erp218_Docs` (генератор
документации), `Service_Erp218_Inventory` (общий формат таблиц инвентаря).
Задачи Minion: `Task_Module_Context`, `Task_Module_Docs`, `Task_Module_List`.
