# erp408_shopfloor — цех

Модуль закрывает разрыв между «заказ в производстве» (erp402) и «сколько
реально сделано у станка». Он отвечает на вопросы мастера и начальника цеха:

- **где работают** — рабочие центры и участки с производительностью и
  стоимостью нормо-часа;
- **когда работают** — смены и рабочий календарь (будни, выходные, сокращённые
  дни, ремонт);
- **что делать** — маршрут производственного заказа: операции из техкарты
  (erp228), разложенные по центрам, сменам и дням;
- **сколько сделано** — факт: годные, брак, время работы, простои.

## Состав модуля

| Слой | Файлы | Что делает |
| --- | --- | --- |
| Миграции | `migrations_pg/pgMigration_001..002` | пять таблиц `erp_408_*` и стартовые данные (3 центра, 3 смены, календарь на месяц) |
| Модели | `Model/Erp408/{WorkCenter,Shift,Operation,Worklog}` | справочники, статусы, подписи, прогресс |
| Сервисы | `Service/Erp408/{WorkCenters,Shifts,Operations}` | правила: маршрут, назначение, отметки, выработка, простои, сводки |
| Контроллеры | `Controller/Erp408/{Main,Index,Operations,Terminal,Centers,Shifts,Api,Widget}` | интерфейс, терминал, справочники, JSON API, виджеты |
| Задача MCP | `mcp.php` | 19 инструментов агента: загрузка, операции, отметки, маршрут |

Таблицы:

1. `erp_408_work_centers` — рабочие центры и участки (`kind`: `center`/`area`),
   производительность и стоимость нормо-часа;
2. `erp_408_shifts` — шаблоны смен (первая, вторая, ночная);
3. `erp_408_calendar` — конкретные дни: сколько часов работает центр (пустой
   центр — «в целом по цеху»); уникальность дня задана выражением с `COALESCE`,
   потому что `NULL` в обычном индексе PostgreSQL считается разным;
4. `erp_408_operations` — операции заказа: план, факт, время, простой, статус;
5. `erp_408_worklogs` — журнал отметок исполнителя. Пополняется **только
   добавлением**: по нему считается время работы и видно, кто и когда нажимал
   кнопку — в терминальном режиме это основное доказательство.

## Как это работает

```
заказ erp402 ──plan_order()──> маршрут операций цеха ──assign()──> центр + смена + день
                                        │
                                        ├── терминал: старт / пауза / выработка / простой / финиш
                                        │        (каждая кнопка — запись в erp_408_worklogs)
                                        └── событие erp408.operation.completed ──> erp402 (журнал заказа)
                                                                                   erp409 (себестоимость, план)
```

Контракт с производством — один метод:

```php
Service_Erp408_Operations::instance()->plan_order(Model_Erp402_Order $order, $user_id = NULL): int
```

`Service_Erp402_Orders::plan_operations()` вызывает его под `class_exists()`,
поэтому модуль можно снять без правки производства. Обратный поток — событие
`erp408.operation.completed` с агрегатом по заказу (`operations_done`,
`operations_total`, `qty_ok_total`): производство само решает, что записать.

**Цех не пишет в чужие таблицы.** `order_id`, `item_id` — мягкие ссылки без
внешних ключей; склад, номенклатура и техкарты читаются через сервисы соседних
модулей.

**Каскад со стороны производства.** Отмена заказа закрывает его операции
(`cancel_for_order()`), удаление — удаляет (`delete_for_order()`); операция в
работе или на паузе блокирует удаление заказа (производство отвечает `locked`).
Иначе терминал показывал бы работу по заказу, которого больше нет.

## Маршруты

| Адрес | Что делает |
| --- | --- |
| `GET /shopfloor` | загрузка цеха на день: центры, операции, очередь заказов без маршрута |
| `POST /shopfloor/plan` | разложить маршрут заказа (из очереди) |
| `GET /shopfloor/operations` | список операций с фильтрами |
| `GET /shopfloor/operations/view/<id>` | карточка операции: план, факт, время, журнал отметок |
| `POST /shopfloor/operations/act/<action>/<id>` | старт, пауза, выработка, простой, завершение, назначение, отмена, удаление |
| `POST /shopfloor/operations/plan`, `/replan`, `/save` | маршрут заказа, пересборка, ручная операция |
| `GET /shopfloor/terminal` | терминал: задания центра с крупными кнопками |
| `GET /shopfloor/terminal/find?code=` | поиск задания по коду с места (`ПО-…`, `ПО-…/30`, № операции) |
| `GET /shopfloor/centers`, `GET/POST .../edit`, `/save`, `/toggle/<id>`, `/delete/<id>` | справочник рабочих центров |
| `GET /shopfloor/shifts`, `POST .../save`, `/toggle/<id>`, `/delete/<id>`, `/day`, `/generate` | смены и календарь |
| `/shopfloor/api/<action>` | JSON API: `stats`, `board`, `operations`, `operation`, `terminal`, `queue`, `centers`, `shifts`, `plan`, `act` |
| `/shopfloor/widget/<action>` | виджеты: `summary`, `order_operations` (маршрут в карточке заказа), `operation_card` |

## Права

| Право | Кому | Что разрешает |
| --- | --- | --- |
| `erp408.view` | admin, manager, accountant | загрузка, операции, отчёты |
| `erp408.manage` | admin, manager | маршруты, центры, смены, календарь, отмена и удаление |
| `erp408.terminal` | admin, manager, accountant | отметки работы (старт, пауза, выработка, простой, финиш) |
| `erp408.*` | admin | всё |

Права объявлены в `application/config/acl.php`; действия контроллеров сверяются
с ними через `can()`.

## Терминал

Страница рассчитана на планшет у станка: крупные кнопки, остаток по операции,
простой виден сразу. Каждое нажатие — запись в `erp_408_worklogs` с
пользователем и временем, поэтому спорные ситуации разбираются по журналу, а не
по памяти. Поле «код задания с места» принимает номер заказа, номер-операцию
(`ПО-2026-000001/30`) и идентификатор операции.

## Инструменты агента (MCP)

`mcp.php` объявляет 19 инструментов: чтение (`shopfloor.board`,
`shopfloor.operations.search`, `shopfloor.operation.get`,
`shopfloor.terminal.tasks`, `shopfloor.stats`, `shopfloor.queue`,
`shopfloor.centers.list`, `shopfloor.shifts.list`), отметки
(`shopfloor.operation.start|pause|resume|output|downtime_start|downtime_stop`)
и управление (`shopfloor.operation.assign`, `shopfloor.route.plan`,
`shopfloor.operation.cancel|delete`). Завершение операции и планирование
маршрута требуют подтверждения человека — агент готовит работу, закрывает её
мастер.

## Проверка и данные

```bash
bin/console db:migrate                 # применить миграции модуля
bin/test --filter=Erp408               # тесты цеха на реальной БД
bin/console dev:smoke                  # маршруты внутри процесса
bin/console mcp:tools | grep shopfloor # инструменты агента
```

Миграция 002 заводит три демонстрационных центра (`СТ-01`, `СБ-01`, `ОТК-01`),
три смены (`S1`–`S3`) и календарь текущего месяца; всё это правится в
интерфейсе. Календарь можно перегенерировать кнопкой «Заполнить месяц».

Тесты (`tests/Unit/Erp408ShopfloorTest.php`) работают на своих данных
(`ТЕСТ-408-*`) и удаляют их в `tearDown`. Записи в журнале аудита (erp119),
созданные действиями тестов, остаются — журнал не чистится по своему смыслу.

## Ограничения и что дальше

- Нормо-часы центра пока не влияют на себестоимость: расчёт — задача erp409
  (данные для него уже пишутся: `worked_sec`, `cost_per_hour`, `qty_scrap`).
- Нет автоматического закрытия заказа в производстве: выпуск продукции
  оформляет склад по документу (`Service_Erp402_Orders::complete()`), цех только
  сообщает о выполнении операций.
- Брак фиксируется количеством; причины брака (коды дефектов) появятся в
  erp409 вместе с отчётом по качеству.
