# Центр уведомлений (ERP217)

Модуль предназначен для централизованного управления уведомлениями пользователей через различные каналы (Email, Telegram, Push, Max). Система работает на основе событийной модели: модули генерируют события, а Центр уведомлений обрабатывает их согласно подпискам.

## Инструкция для программиста: как настроить уведомления в любом модуле

Чтобы ваш модуль начал отправлять уведомления через Центр уведомлений, необходимо выполнить 4 шага.

### 1. Генерация события (Publish)
В коде вашего модуля в местах, где требуется уведомление (например, создание сделки или смена статуса), необходимо вызвать системное событие через класс `Event`.

**Пример из модуля `erp221_crm`:**
```php
// В методе создания сделки
Event::fire('erp221.deal.created', [
    'deal_id'    => $deal->id,
    'title'      => $deal->title,
    'amount'     => $deal->amount,
    'target_user_id' => $manager_id // ID того, кто должен получить уведомление
]);
```
*Важно: Если в `payload` передано поле `target_user_id`, система отправит уведомление этому пользователю. Если поле отсутствует, инициатором и получателем по умолчанию будет текущий авторизованный пользователь.*

### 2. Регистрация типа события в конфигурации
Добавьте ваше событие в файл конфигурации Центра уведомлений `/application/config/erp217_notification_center.php`, чтобы оно появилось в интерфейсе настроек подписок.

```php
'event_types' => [
    'erp221.deal.created' => 'Новая сделка в CRM',
    'erp221.activity.added' => 'Добавление активности в таймлайн',
    // ...
],
```

### 3. Создание шаблонов сообщений
В базе данных (таблица `erp_217_templates`) или через административный интерфейс необходимо создать шаблоны для нужных каналов.
* **Alias:** `erp221.deal.created`
* **Subject:** "Новая сделка: {{title}}"
* **Body:** "Здравствуйте! Создана новая сделка №{{deal_id}} на сумму {{amount}}."

*Переменные в двойных фигурных скобках `{{key}}` автоматически заменяются данными из массива `payload`, переданного в `Event::fire`.*

### 4. Связка события с Центром уведомлений (Подписка)
Чтобы `EventBus` (модуль `erp208`) понимал, что событие нужно проксировать в Центр уведомлений, необходимо создать запись в таблице подписчиков.

**Как добавить подписчика:**
1. Перейдите в модуль **"Управление событиями"** (`/erp208_events`).
2. Зайдите в раздел **"Список подписчиков"** -> **"Создать новую подписку"**.
3. Заполните поля:
    * **Event Name:** `erp221.deal.created` (точное имя события).
    * **Module ID:** `erp217_notification_center` (указываем, кто обрабатывает).
    * **Is Notification:** Поставьте галочку (флаг `is_notification = 1`).
    * **Is Active:** Поставьте галочку.
4. Сохраните.

**Что происходит внутри:**
При загрузке `EventBus` метод `_load_subscribers_from_db()` находит эту запись. Видя флаг `is_notification`, он регистрирует слушателя:
`$this->listen($event_name, array($this, '_proxy_to_notification_center'));`
Теперь при каждом вызове `Event::fire` для этого события будет автоматически вызываться прокси-метод, который передаст данные в `Service_Erp217_Bus`.

## Как это работает (на примере CRM erp221)

### Цепочка прохождения уведомления:
1. **Триггер:** В модуле CRM вызывается `Service_Erp221_Timeline::add_activity`.
2. **Событие:** Внутри метода срабатывает `Event::fire('erp221.activity.added', [...])`.
3. **Шина событий:** Класс `Event` передает данные в `Service_Erp208_EventBus`.
4. **Прокси:** `EventBus` видит, если в событии `payload` которых содержит специфический атрибут (`is_notification => true` или наличие `target_user_id`),то автоматически направляется в `_proxy_to_notification_center` без явной регистрации в таблице подписчиков.
5. **Центр уведомлений:** `Service_Erp217_Bus::send()` проверяет:
    * Подписан ли пользователь `target_user_id` на событие `erp221.activity.added`.
    * Какие каналы у него включены (Email, Telegram и т.д.).
    * Есть ли шаблоны для этих каналов.
6. **Очередь:** Если всё ок, сообщения рендерятся и попадают в таблицу `erp_217_notification` со статусом `pending`.
7. **Отправка:** Фоновый процесс (Cron) вызывает задачу обработки очереди.

## Фоновая обработка (Cron)

Для физической отправки уведомлений, находящихся в очереди, необходимо настроить выполнение задачи Minion на сервере.

**Команда для запуска вручную:**
```bash
php /home/c/cs11853/test.promerp.ru/public_html/index.php --task=Erp217:Process
```

**Настройка в Crontab:**
Рекомендуется запускать задачу каждую минуту:
```bash
* * * * * /usr/bin/php /home/c/cs11853/test.promerp.ru/public_html/index.php --task=Erp217:Process > /dev/null 2>&1
```

## Настройка уведомлений для пользователя

Пользователь может самостоятельно управлять своими уведомлениями в интерфейсе модуля:

1. Перейти в раздел **"Мои уведомления"** (`/erp217_index`).
2. Открыть вкладку **"Настройки подписок"** (`/erp217_index/settings`).
3. В появившейся матрице (События x Каналы) проставить галочки напротив нужных уведомлений.
    * *Например: получать "Новая сделка" по Email и Telegram, а "Удаление активности" — только в Push.*
4. Нажать "Сохранить".

## Мониторинг и отладка
Администраторы могут отслеживать статус отправки в разделе **"Мониторинг очереди"** (`/erp217_notification`). Там доступны:
* Просмотр текста отправленного сообщения.
* Логи ошибок (если письмо не ушло).
* Кнопка "Retry" для повторной отправки упавших уведомлений.
* Тестовая отправка любого события через API: `/erp217_api/test_send?alias=erp221.deal.created&user_id=1`.
