# Анализ реализации единиц измерения (UOM) для свойств MDM

Для реализации выбора единиц измерения (UOM) по умолчанию и возможности их выбора в интерфейсе, необходимо внести изменения в структуру схемы (JSON), логику контроллера и представления.

### 1. Изменения в БД и Схемах (JSON)
В файле `БД_онтология_v5.6.sql` и миграции `pgMigration_002_erp230_mdm_add_data.php` необходимо расширить описание свойств в `types.schema`.
Используем стандартное расширение `x-uom` для указания единицы измерения по умолчанию.

**Пример обновленной схемы для типа `resistor`:**
```json
{
  "properties": {
    "resistance": {
      "type": "number",
      "title": "Сопротивление",
      "x-uom": "ohm"
    },
    "tolerance": {
      "type": "string",
      "title": "Допуск",
      "x-uom": "%"
    }
  }
}
```

### 2. Изменения в Controller_Erp230_Objects
Файл: `/application/modules/erp230_mdm/classes/Controller/Erp230/Objects.php`

В методах `action_create`, `action_edit` и `action_batch` необходимо передать список всех доступных UOM в View, чтобы пользователь мог выбирать из справочника.

```php
// В методах action_create, action_edit, action_batch добавить:
->set('uoms', ORM::factory('Erp230_Uom')->find_all()->as_array())
```

### 3. Изменения в View Формы
Файл: `/application/modules/erp230_mdm/views/erp230/objects/form.php`

Необходимо заменить текстовое поле ввода UOM на выпадающий список (select) или комбинированный ввод (datalist), инициализируемый из схемы.

**Логика в JS (внутри form.php):**
При смене типа объекта и загрузке схемы, скрипт должен автоматически подставлять `x-uom` в поле единицы измерения.

```javascript
// В функции loadSchema(typeId) изменить генерацию HTML:
const uomDefault = def['x-uom'] || '';
// Вместо обычного input для attr_uom[]:
html += `
<select name="attr_uom[]" class="w-24 rounded-lg border ...">
    <option value="">—</option>
    ${uomOptionsHtml} 
</select>`;
// Где uomOptionsHtml заранее сформирован из переданного массива $uoms
```

### 4. Изменения в Service_Erp230_ObjectFactory
Файл: `/application/modules/erp230_mdm/classes/Service/Erp230/ObjectFactory.php`

Метод `_normalize_properties` уже поддерживает поле `uom`. Важно убедиться, что при создании объекта через API или Batch-загрузку, если `uom` не передан в payload, сервис пытается взять его из схемы типа (через `Service_Erp230_SchemaValidator`).

### 5. Изменения в Модели Property (SQL)
Файл: `БД_онтология_v5.6.sql`

Функция `upsert_property` уже принимает `p_uom`. Она корректно записывает данные в `object_properties.uom_code`.

### Резюме необходимых действий:
1. **Обновить справочник `uom`** в БД (добавить недостающие единицы: %, ppm, °C).
2. **Обогатить `types.schema`** во всех миграциях, добавив `"x-uom": "код"` к числовым параметрам.
3. **Модифицировать `form.php`**:
    - Передать массив `$uoms`.
    - В JS-шаблоне `tpl-extra-row` и в цикле генерации полей схемы заменить `input attr_uom` на `select` или `input list="uom-list"`.
    - Добавить `<datalist id="uom-list">` со всеми кодами UOM для удобства поиска.
4. **В контроллере `Objects.php`** добавить метод `_dict_uoms()` (аналогично `_dict_types`) для кэширования списка единиц измерения.
