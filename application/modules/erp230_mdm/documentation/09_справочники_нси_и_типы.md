Справочники НСИ и типы объектов (v5.3)

Настоящий документ описывает структуру нормативно-справочной информации (НСИ), классификацию типов объектов и механизмы управления метаданными в системе MDM.

### 1. Организационная структура (org_units)

Система поддерживает многоуровневую иерархию организаций, что позволяет изолировать данные подразделений или дочерних обществ.

*   **Идентификация:** Используются строковые ID (например, `PERM_MOTORS`), что упрощает интеграцию с внешними ERP-системами.
*   **Иерархия (ltree):** Поле `path` хранит полный путь в дереве (например, `HOLDING.PLANT1.SHOP5`). Это обеспечивает:
    *   Мгновенную проверку прав доступа (RLS).
    *   Агрегацию данных по всей ветке организации.
*   **Наследование:** При создании объекта он автоматически наследует `org_path` своей организации.

### 2. Типы объектов и классификатор (types)

Классификация объектов в MDM строится на основе дерева типов, где каждый тип может определять структуру данных для своих экземпляров.

*   **Древовидная структура:** Типы организованы иерархически (например, `component` -> `electronic` -> `microchip`).
*   **JSON-схемы:** Поле `schema` содержит описание обязательных и опциональных атрибутов для данного типа. Схемы используются для валидации данных при импорте.
*   **Наследование свойств:** Дочерние типы наследуют правила валидации от родительских.

### 3. Источники данных (sources)

Каждая запись в MDM должна быть привязана к источнику. Источники определяют уровень доверия к данным.

*   **Trust Score (0-100):** Числовой показатель, используемый в алгоритме арбитража `upsert_property`.
*   **Типизация источников:**
    *   `plm`: Инженерные данные (высокое доверие).
    *   `erp`: Учетные данные (среднее доверие).
    *   `manual`: Ручной ввод экспертом (наивысшее доверие).
    *   `ai`: Результаты работы алгоритмов (низкое доверие).

### 4. Единицы измерения (uom)

Справочник UOM (Units of Measure) обеспечивает сопоставимость числовых значений.

*   **Базовые единицы:** Поддержка коэффициентов пересчета (`factor`) относительно базовой единицы (например, `mm` -> `m`).
*   **Нормализация:** При сохранении свойств система проверяет соответствие `uom_code` справочнику.

### 5. Реестр мастер-кодов (object_codes)

Для обеспечения глобальной уникальности идентификаторов используется таблица-реестр `object_codes`.

*   **Бизнес-логика:** В отличие от UUID, мастер-код является человекочитаемым (артикул, серийный номер).
*   **Уникальность:** Система гарантирует уникальность связки `UPPER(master_code) + type_id + org_id`. Это предотвращает создание дублей при импорте из разных систем под одним и тем же кодом.

### 6. Пользователи и роли (users)

Управление доступом осуществляется через привязку пользователя к организации и роли.

*   **Viewer:** Доступ на чтение объектов своей ветки `org_path`.
*   **Editor:** Право на создание и редактирование свойств в рамках своей организации.
*   **Admin:** Полный доступ, включая управление справочниками `types`, `sources` и выполнение операций слияния (Merge).

### 7. Механизм расширения метаданных

Система позволяет добавлять новые типы атрибутов без изменения схемы БД:
1.  Добавление нового ключа в JSON-схему соответствующего `type`.
2.  Обновление документации по API для потребителей.
3.  Автоматическое появление поля в денормализованной таблице `object_state` после первого обновления объекта.
