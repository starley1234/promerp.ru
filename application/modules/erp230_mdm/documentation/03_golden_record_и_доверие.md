Golden Record и механизмы доверия (v5.3)

Настоящий документ подробно описывает логику формирования «Золотой записи» (Golden Record) в системе MDM, алгоритмы арбитража данных при конфликтах и систему числовых показателей доверия.

### 1. Концепция Golden Record

В распределенной среде крупного холдинга данные об одном и том же объекте (например, авиационном двигателе) могут поступать из разных систем: PLM (конструкторские данные), ERP (учетные данные), MES (данные с производства) или систем ручного ввода.

**Золотая запись** — это динамически формируемый набор наиболее достоверных атрибутов объекта, полученный путем автоматического выбора лучших значений из всех доступных источников.

### 2. Уровни доверия (Trust Score)

Каждый источник данных в таблице `sources` имеет обязательный параметр `trust` (целое число от 0 до 100).

*   **Высокое доверие (90-100):** Инженерные системы (PLM, Teamcenter), государственные реестры, ручной ввод авторизованным экспертом.
*   **Среднее доверие (50-89):** Учетные системы (ERP), системы планирования.
*   **Низкое доверие (0-49):** Системы автоматического распознавания (AI/OCR), временные файлы, внешние справочники поставщиков.

### 3. Алгоритм арбитража (Функция upsert_property)

Центральным механизмом управления достоверностью является хранимая процедура `upsert_property`. Она реализует логику «вытеснения» менее надежных данных более надежными.

#### Логика работы:
1.  **Идентификация:** Система находит текущее активное значение свойства (`is_current = true`) для конкретного `object_id` и `key`.
2.  **Сравнение:** Извлекается `trust` источника текущего значения и `trust` нового источника.
3.  **Принятие решения:**
    *   Если `New_Trust >= Current_Trust`: Новое значение принимается. Текущая запись «закрывается» (устанавливается дата окончания в `valid_period`), и создается новая запись с новым значением.
    *   Если `New_Trust < Current_Trust`: Новое значение отклоняется. Функция возвращает код `rejected_low_trust`, изменение не фиксируется в истории.
4.  **Обновление состояния:** При успешном обновлении вызывается `refresh_object_state`, которая пересчитывает «плоский» вид объекта в таблице `object_state`.

### 4. Уверенность в данных (Confidence)

Помимо доверия к источнику (`trust`), каждое конкретное значение может иметь показатель уверенности (`confidence`) от 0.0 до 1.0. 

*   Используется преимущественно для данных, полученных через AI или вероятностные алгоритмы.
*   Если два значения приходят из одного источника, система может использовать `confidence` как дополнительный критерий для выбора наиболее точного измерения.

### 5. Конфликты и ручное переопределение

В исключительных случаях, когда автоматический арбитраж не может разрешить противоречие (например, два источника с одинаковым уровнем доверия предоставляют разные данные), применяется механизм **Expert Override**:

1.  Специалист с ролью `admin` вносит значение вручную.
2.  Источник `manual` обладает наивысшим приоритетом (100).
3.  Это значение блокирует автоматические обновления от систем с меньшим приоритетом до тех пор, пока администратор не снимет блокировку или не появится источник с аналогичным уровнем доверия.

### 6. Прослеживаемость (Lineage)

Благодаря модели EAV + Time-Travel, система сохраняет полную историю «борьбы» за золотую запись:
*   В таблице `object_properties` хранятся все когда-либо принятые значения.
*   Поле `source_id` позволяет точно определить, какая система была «автором» значения в любой момент времени.
*   Аудит отклоненных записей (логов `upsert_property`) позволяет анализировать качество данных во внешних системах-источниках.

### 7. Практический пример

1.  **T0:** Система **ERP** (trust=70) передает вес детали: `15.5 кг`. Значение записывается как текущее.
2.  **T1:** Система **PLM** (trust=90) передает вес той же детали: `15.42 кг`.
    *   *Результат:* `90 > 70`. Значение ERP уходит в историю, значение PLM становится «Золотым».
3.  **T2:** Система **AI-Scanner** (trust=30) передает вес: `16.0 кг`.
    *   *Результат:* `30 < 90`. Значение отклоняется. Золотая запись остается неизменной (`15.42 кг`).
