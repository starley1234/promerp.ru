Поиск и векторные эмбеддинги (v5.3)

Настоящий документ описывает механизмы поиска в системе MDM, включая классический полнотекстовый поиск, фильтрацию по атрибутам и инновационный семантический поиск на основе векторных эмбеддингов.

### 1. Полнотекстовый поиск (FTS)

Для быстрого поиска по текстовым описаниям, кодам и названиям используется встроенный механизм PostgreSQL Full Text Search.

*   **Индексация**: В таблице `object_state` поле `search` имеет тип `tsvector`. Оно автоматически обновляется при изменении свойств объекта.
*   **Веса**: При формировании поискового индекса мастер-коду присваивается наивысший приоритет (вес 'A'), названиям — 'B', а прочим текстовым атрибутам — 'C'.
*   **Запросы**: Поддерживается морфология русского и английского языков. Поиск осуществляется через оператор `@@` с использованием `to_tsquery`.

### 2. Поиск по атрибутам (JSONB)

Благодаря денормализованной структуре в `object_state`, система поддерживает мгновенную фильтрацию по любым характеристикам.

*   **GIN-индексы**: Поле `attributes` (jsonb) проиндексировано с использованием `jsonb_path_ops`. Это позволяет выполнять запросы вида «найти все детали с весом > 100 кг и материалом 'Титан'» за миллисекунды.
*   **Синтаксис**: Используются стандартные операторы PostgreSQL для JSONB (`@>`, `?`, `->>`).

### 3. Векторные эмбеддинги и семантический поиск

Для решения задач поиска дубликатов и подбора аналогов (цифровых двойников) в систему интегрировано расширение `pgvector`.

#### 3.1. Концепция эмбеддингов
Каждый объект может быть представлен в виде многомерного вектора (эмбеддинга) размерностью 1024. Этот вектор отражает «смысл» объекта на основе его характеристик, иерархии и связей.

#### 3.2. Таблица object_embeddings
*   **embedding**: Поле типа `vector(1024)`.
*   **model**: Название модели (например, `multilingual-e5-large`), использованной для генерации вектора.
*   **Индекс HNSW**: Используется индекс Hierarchical Navigable Small World (`ix_emb_hnsw`) для обеспечения сверхбыстрого поиска ближайших соседей в векторном пространстве.

#### 3.3. Семантическое сходство
В отличие от поиска по ключевым словам, векторный поиск находит объекты, похожие по сути:
*   Запрос «Крепеж для высоконагруженных узлов» найдет соответствующие болты и шпильки, даже если в их названии нет слова «крепеж».
*   Расстояние вычисляется с помощью косинусного сходства (`vector_cosine_ops`).

### 4. Поиск по иерархии (LTree)

Поиск вглубь по организационной структуре или классификатору типов реализован через расширение `ltree`.

*   **Операторы**:
    *   `path <@ 'ROOT.PLANT1'`: Найти все объекты завода №1 и всех его цехов.
    *   `path ~ 'ROOT.*.SHOP5'`: Найти все «Цеха №5» во всех филиалах.
*   **Производительность**: Использование GIST-индексов на полях `org_path` и `path` типов обеспечивает логарифмическую скорость поиска даже при миллионах записей.

### 5. Интеграция в бизнес-логику

Механизмы поиска используются в следующих процессах:

1.  **Предотвращение дублей**: При создании нового объекта система автоматически выполняет векторный поиск. Если найден объект с близостью > 0.95, пользователю предлагается использовать существующую запись или запустить процедуру слияния (Merge).
2.  **Подбор аналогов**: Инженеры могут искать замену компоненту, основываясь на близости векторов характеристик (Digital Twin Matching).
3.  **Глобальный поиск**: Единая поисковая строка в интерфейсе комбинирует результаты FTS (по кодам) и векторного поиска (по смыслу).

### 6. Обновление индексов

*   **Синхронно**: Обновление `object_state` и `tsvector` происходит мгновенно при вызове `refresh_object_state` (внутри транзакции `upsert_property`).
*   **Асинхронно**: Пересчет векторных эмбеддингов выполняется фоновым процессом (Worker) через внешнюю LLM-модель, так как это ресурсоемкая операция. После обновления вектора обновляется поле `updated_at` в `object_embeddings`.
