Правила добавления объектов в систему MDM (v5.3)

Настоящий документ определяет регламент и технические нюансы внесения данных в реестр мастер-данных. Система MDM построена на принципах «Золотой записи» (Golden Record), где достоверность данных определяется уровнем доверия источника.

### 1. Способы добавления объектов

#### А. Автоматизированный импорт (Основной)
Используется для массовой загрузки данных из внешних систем (PLM, ERP, MES).
*   **Механизм:** Данные поступают через API или сервис консолидации (`Service_Erp230_Consolidation`).
*   **Технический нюанс:** При импорте обязательно заполняется таблица `object_xref`. Это связка «ID внешней системы» + «ID MDM». Она позволяет при повторном импорте не создавать дубль, а обновлять свойства существующего объекта.
*   **Пример:** Если из Teamcenter пришел агрегат с ID `TC-999`, система проверяет `object_xref`. Если запись есть — вызывается `upsert_property`, если нет — создается новый `object`.

#### Б. Ручной ввод
Используется для создания уникальных объектов или уточнения данных «на лету».
*   **Механизм:** Интерфейс модуля `erp230_mdm`.
*   **Организационный нюанс:** Ручной ввод имеет фиксированный `source_id = 'manual'`. Уровень доверия (trust) для ручного ввода обычно устанавливается выше, чем у автоматических систем (например, 95-100), чтобы оператор мог перекрыть ошибочные данные из систем.

---

### 2. Мастер-коды (Идентификация)

Мастер-код (`master_code`) — это человекочитаемый уникальный идентификатор объекта в рамках его типа и организации.

*   **Откуда брать:**
    1.  **Внешний стандарт:** Если объект имеет ГОСТ, артикул производителя или серийный номер (например, `SN-AL-2024-001`), используется он.
    2.  **Генерация MDM:** Если внешнего кода нет, MDM генерирует код по маске: `[TYPE_ID]-[ORG_ID]-[SEQUENCE]`.
*   **Технические требования:**
    *   Регистр не важен (система приводит к `UPPER` при проверке).
    *   Запрещены спецсимволы, кроме дефиса и подчеркивания.
*   **Контроль уникальности:** За это отвечает таблица `object_codes`. Попытка вставить дублирующий код в связке с тем же типом и организацией вызовет ошибку на уровне БД (`Primary Key violation`).

### 3. Предотвращение и обработка дублей

#### Как минимизировать появление дублей:
1.  **Проверка по XREF:** Перед созданием нового объекта всегда проверяется наличие `remote_id` в таблице `object_xref`.
2.  **Семантический поиск:** При ручном вводе система использует `Model_Erp230_Search::semantic_search`. Если пользователь вводит «Двигатель ПД-14», система через векторный поиск покажет похожие уже существующие объекты, даже если их коды различаются.
3.  **Валидация схем:** Для каждого типа объекта в таблице `types` прописана JSON-схема. Она не дает создать объект с неполным набором ключевых атрибутов, по которым можно идентифицировать дубль.

#### Если дубли появились (Процедура слияния):
Если в системе обнаружены две записи, описывающие один физический объект, запускается процесс **Merge**:
1.  **Выбор победителя (Winner):** Объект с наиболее полной историей или более высоким статусом.
2.  **Перенос данных:** Все свойства (`object_properties`) и связи (`object_links`) «проигравшего» объекта перепривязываются к «победителю».
3.  **Статус Merged:** «Проигравшему» объекту присваивается терминальное состояние `state = 'merged'`, а в поле `merged_into` записывается UUID победителя.
4.  **Фиксация:** Операция слияния автоматически создает запись в `baselines` для аудита.

### 4. Технический алгоритм добавления (Шпаргалка)

При добавлении объекта (программно или вручную) необходимо соблюдать последовательность:

1.  **Инициализация объекта:**
    ```sql
    INSERT INTO objects (type_id, org_id, master_code, state) 
    VALUES ('engine', 'PERM_MOTORS', 'PD-14-001', 'draft') 
    RETURNING id;
    ```
    *Триггер `trg_objects_before_ins` автоматически проверит уникальность кода и пропишет `org_path`.*

2.  **Добавление атрибутов (только через функцию!):**
    Никогда не делайте `INSERT` в `object_properties` напрямую. Используйте:
    ```sql
    SELECT upsert_property(
        'UUID_ОБЪЕКТА', 
        'weight', 
        '{"value": 2870}'::jsonb, 
        'plm', 
        'kg'
    );
    ```
    *Это обеспечит версионность (Time-Travel) и проверку уровня доверия (Trust Score).*

3.  **Создание связей (BOM):**
    Добавьте записи в `object_links`, указав `parent_id` и `child_id`.

4.  **Фиксация состояния:**
    После завершения ввода вызовите смену состояния на `active` через модель, что автоматически обновит денормализованную таблицу `object_state` для быстрого поиска.
