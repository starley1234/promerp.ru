Структуры BOM и связи (v5.3)

Настоящий документ описывает механизмы управления структурами изделий (Bill of Materials — BOM), иерархическими связями и графами зависимостей в системе MDM.

### 1. Типы структур (EBOM, MBOM, SBOM)

Система поддерживает одновременное существование нескольких типов структур для одного и того же объекта, что позволяет реализовать концепцию цифрового двойника на разных этапах жизненного цикла.

*   **EBOM (Engineering BOM):** Конструкторская структура, отражающая состав изделия согласно проектной документации.
*   **MBOM (Manufacturing BOM):** Технологическая структура, учитывающая особенности производства (оснастку, вспомогательные материалы, последовательность сборки).
*   **SBOM (Service BOM):** Эксплуатационная структура, содержащая перечень заменяемых компонентов и расходных материалов.

Тип структуры определяется полем `link_type` в таблице `object_links`.

### 2. Модель связей (Таблица object_links)

Связи в MDM не являются жестко закрепленными в таблице объектов, а вынесены в отдельный реестр, что позволяет строить графы любой сложности.

#### Ключевые поля:
*   **parent_id / child_id:** Ссылки на UUID объектов. Запрещены циклические ссылки (проверяется триггером).
*   **qty (Количество):** Числовое значение вхождения компонента в родительский узел.
*   **designator:** Позиционное обозначение (например, «R1, R2» для электроники или «Поз. 12» для механики).
*   **valid_period (tstzrange):** Временной интервал актуальности связи. Позволяет хранить историю изменения состава изделия.

### 3. Версионность структур и Time-Travel

Благодаря использованию типа `tstzrange` для каждой связи, система может реконструировать состав изделия на любой момент времени в прошлом.

*   **Текущий состав:** Выбираются связи, где `upper(valid_period) IS NULL`.
*   **Исторический срез:** Выбираются связи, в интервал которых попадает искомая дата.
*   **Замена компонента:** При замене детали в составе изделия старая связь «закрывается» текущей датой, и создается новая запись с новым `child_id`.

### 4. Механизм разузлования (Explosion)

Для получения полного состава изделия (на всю глубину вложенности) используется рекурсивное сканирование графа.

#### Алгоритм работы:
1.  **Поиск корня:** Выборка всех `child_id` для заданного `parent_id`.
2.  **Рекурсия:** Для каждого найденного `child_id` выполняется поиск его собственных компонентов.
3.  **Агрегация:** Суммирование количеств (`qty`) с учетом коэффициентов вложенности.
4.  **Проверка циклов:** Встроенная защита предотвращает бесконечную рекурсию при наличии ошибок в данных.

### 5. Интеграция с бейслейнами

Бейслейн (Baseline) объекта может включать в себя не только плоский список атрибутов, но и снимок его структуры.

*   **Snapshot структуры:** При создании бейслейна в поле `snapshot` сохраняется массив связей, актуальных на момент фиксации.
*   **Целостность:** Если компонент внутри структуры был изменен или удален, хэш-сумма бейслейна родительского объекта позволит выявить расхождение между зафиксированным «эталоном» и текущим состоянием БД.

### 6. Правила валидации связей

При создании связи (`INSERT` в `object_links`) система проверяет следующие бизнес-правила:

1.  **Статус родителя:** Нельзя добавлять компоненты в объект, находящийся в состоянии `Archived` или `Merged`.
2.  **Типовая совместимость:** Проверка по матрице разрешенных связей (например, «Двигатель» может содержать «Лопатку», но не может содержать «Цех»).
3.  **Единицы измерения:** Если у связи указано `qty`, система проверяет совместимость единиц измерения (UOM) компонента.

### 7. Производительность графовых запросов

Для обеспечения высокой скорости работы с глубокими структурами (10+ уровней вложенности, тысячи компонентов):

*   **Индексация:** Используются GIST-индексы по полю `valid_period` и классические индексы по `parent_id`.
*   **Кеширование:** Результаты разузлования часто запрашиваемых изделий могут кешироваться в денормализованном виде в связанных сервисах.
*   **Материализованные пути:** Для определенных типов иерархий (например, оргструктура) используется расширение `ltree`, позволяющее получать всё дерево одним индексным запросом без рекурсии.
