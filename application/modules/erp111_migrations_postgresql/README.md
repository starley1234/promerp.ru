# Миграции PostgreSQL — erp111

Модуль находит `migrations_pg/pgMigration_*.php` во всех подключённых модулях,
ведёт отдельный реестр `migrations_pg` в каждой группе БД и применяет каждую
миграцию в транзакции.

## Запуск из браузера — основной способ для администратора

1. Войдите под пользователем с правом `erp111.manage` (у роли `admin` оно есть).
2. Откройте `/migrate_pg` или пункт **Администрирование → Миграция БД**.
3. Проверьте число ожидающих миграций.
4. Нажмите **Применить ожидающие миграции** и подтвердите действие.
5. Дождитесь зелёного сообщения. Если ожидает `0`, ничего запускать не нужно.

Запуск выполняется только POST-запросом с CSRF-токеном. Старый адрес
`/migrate_pg?run=1` больше ничего не изменяет и показывает подсказку с кнопкой.
Администратор может пользоваться страницей и в production; анонимный доступ
запрещён. Группы БД выполняются независимо, начиная с `default`: ошибка optional
MDM не блокирует миграции основной ERP. Результат и исходный текст ошибки
показываются прямо на странице.

`default` и `mdm` нельзя направлять в одну физическую базу: у MDM есть собственная
таблица `users`. Используйте, например, `DB_DEFAULT_NAME=promerp` и
`DB_MDM_NAME=promerp_mdm`. Страница явно предупредит о совпадении.

Для служебного стенда в DEVELOPMENT можно задать `MIGRATIONS_TOKEN` и открыть
`/migrate_pg?token=...`. В production токен не заменяет вход администратора.

## CLI для автоматического развёртывания

```bash
bin/console db:migrate             # применить ожидающие
bin/console db:migrate --status    # только состояние
bin/console db:migrate --dry-run   # план без изменений
```

CLI и браузер вызывают один `Service_Erp111_Migrator`, поэтому порядок,
транзакции и реестр миграций совпадают.

## API чтения

Авторизованный администратор может получить состояние без изменения схемы:

- `GET /migrate_pg/api/status`
- `GET /migrate_pg/api/inventory`
- `GET /migrate_pg/api/orphans`

## Создание миграции

Миграция размещается в `<module>/migrations_pg/` и наследует `pgMigration`:

```php
class pgMigration_005_Example extends pgMigration
{
    public function up()   { $this->run_query('CREATE TABLE example (id SERIAL PRIMARY KEY)'); }
    public function down() { $this->run_query('DROP TABLE IF EXISTS example'); }
}
```

Имя класса должно совпадать с именем файла. Порядок определяется порядком
подключения модулей и именем файла внутри модуля. Для новой правки схемы всегда
создаётся новая миграция — уже применённые файлы не редактируются.
