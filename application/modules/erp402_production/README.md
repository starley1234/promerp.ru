# Производство (erp402_production)

**ID модуля:** 402
**Слаг:** `production`
**Слой:** Operations (диапазон 400–599)
**Префикс таблиц:** `erp_402_*`
**Статус:** реализован, миграции применяются, требует PHP 8.4+ и PostgreSQL 13+

---

## 1. Назначение

Модуль ведёт производственные заказы: состав изделия из технологической карты,
резерв и списание материалов, выпуск готовой продукции на склад.

Модуль **не владеет** справочниками и складом — он их использует:

| Данные | Источник | Как обращается |
|---|---|---|
| Номенклатура, единицы измерения | `erp227_core_registry` | `Service_Erp227_*`, поле `item_id` |
| Склады, остатки, резервы, движения | `erp401_wms` | `Service_Erp401_Stock` |
| Технологические карты и маршруты операций | `erp228_tech_cards` | `Service_Erp228_TechCards::operations()` |
| Контрагенты и договоры | `erp301_counterparty` | мягкие ссылки `customer_id`, `contract_id` |
| Журнал действий | `erp119_audit` | `Service_Erp119_Journal::change()` |
| Шина событий | `erp208_events` | `Service_Erp208_EventBus::publish()` |
| Цех, план операций | `erp408_shopfloor` (S2) | `class_exists()`-guard, контракт ниже |

### Возможности

| Функция | Описание |
|---|---|
| **Заказы** | Номер `ПО-ГГГГ-НННННН` из последовательности, изделие, план выпуска, приоритет, срок, заказчик и договор |
| **Состав из техкарты** | Спецификация читается из `structured_data` техкарты: дерево обходится, дублирующиеся материалы суммируются, строки получают `line_no` с шагом 10 |
| **Сопоставление номенклатуры** | Точное совпадение наименования — автоматически, неточное — с пометкой «проверить», отсутствующее — строка без `item_id` (заказ всё равно создаётся) |
| **Потребность** | `норма × план` пересчитывается при любом изменении плана или нормы (`Orders::recalc()`) |
| **Резерв материалов** | При выпуске в производство: резерв под `ref_type = 'erp402_order'`; чего не хватило — строки переходят в статус «не хватает», заказ остаётся планом |
| **Списание** | При выпуске продукции: расход со склада (или закрытие резерва), `qty_issued`, защита от списания без остатка |
| **Выпуск продукции** | Частичный выпуск: `qty_done` растёт, заказ закрывается только при выполнении плана; приёмка идёт на склад готовой продукции |
| **Отмена и удаление** | Отмена снимает резервы и закрывает незакрытые операции цеха; удаление убирает их вместе с заказом (пока операция в работе — отказ `locked`), из `cancelled` заказ можно вернуть в черновик |
| **API и виджеты** | JSON API для интеграций, виджеты для карточек объектов `erp227` и сводки производства |

## 2. Модель данных

`erp_402_orders` — заказ:

| Поле | Назначение |
|---|---|
| `uuid` | идентификатор для журнала и шины событий (`gen_random_uuid()`) |
| `number` | номер `ПО-2026-000123`, уникальный, из `erp_402_order_number_seq` |
| `title`, `tech_card_id`, `item_id`, `uom_code`, `qty`, `qty_done` | изделие и план выпуска |
| `status` | `draft → planned → released → in_progress → done`, `cancelled` из любого незавершённого |
| `priority` (1–9), `target_date` | приоритет и срок |
| `warehouse_id`, `output_warehouse_id` | склад материалов и склад готовой продукции |
| `customer_id`, `contract_id` | мягкие ссылки на `erp301` |
| `planned_materials_cost`, `planned_labor_cost` | плановая себестоимость (заполняется расчётом) |
| `search_text`, `created_by`, `created_at`, `updated_at` | служебные |

`erp_402_order_items` — состав заказа: `line_no` (уникален внутри заказа),
`item_id`, `name` (наименование из спецификации), `uom_code`,
`qty_per_unit` (норма), `qty_total` (потребность), `qty_issued` (списано),
`warehouse_id`, `reservation_id` (резерв `erp401`), `status`
(`planned | reserved | issued | short`), `note`.

Ссылки на другие модули — **мягкие** (без внешних ключей): модули можно
включать и выключать независимо.

## 3. Сервисы

| Сервис | Ответственность |
|---|---|
| `Service_Erp402_Orders` | жизненный цикл заказа: CRUD, состав, `plan/release/start/complete/cancel`, пересчёт, статистика, номера, публикация событий |
| `Service_Erp402_Materials` | потребность и нехватка, резерв, списание, снятие резервов — единственная точка общения со складом |
| `Service_Erp402_Bom` | чтение спецификации и маршрута из техкарты (`erp228`), разбор дерева, сопоставление с номенклатурой |

Правила, которые важно не потерять:

- всё, что меняет остатки, идёт **только** через `Service_Erp401_Stock` (резерв, расход, приёмка);
- нехватка материалов — не исключение: строки помечаются `short`, пользователь получает отчёт;
- выпуск идёт в транзакции: сначала списание, потом приёмка продукции; ошибка откатывает выпуск;
- каждое изменение заказа пишется в журнал `erp119` (`entity_type = 'order'`, `entity_id = uuid`);
- события `erp402.order.{created,updated,deleted,planned,released,started,completed,cancelled}` уходят в `erp208`.

## 4. Маршруты

| Маршрут | Действие |
|---|---|
| `GET /production` | сводка: открытые и просроченные заказы, нехватка материалов |
| `GET /production/orders` | список с фильтрами (статус, поиск, просрочка) и постранично |
| `GET /production/orders/view/<id>` | карточка заказа: состав, потребность, наличие, прогресс |
| `GET|POST /production/orders/edit(/<id>)` | форма заказа |
| `POST /production/orders/save` | создание и изменение |
| `POST /production/orders/fill/<id>` | заполнить состав из техкарты |
| `POST /production/orders/item/save`, `GET /production/orders/item/delete/<order_id>/<id>` | строки состава |
| `GET /production/orders/{plan,release,start,complete,cancel,delete}/<id>` | переходы статуса и удаление |
| `GET /production/api/<action>(/<id>)` | `search`, `get`, `requirements`, `stats`, `transition`, `options` |
| `GET /production/widget/<action>(/<id>)` | `summary`, `order_card`, `object_orders` |

## 6. Контракт с цехом (erp408_shopfloor)

`Service_Erp402_Orders::plan_operations()` проверяет наличие класса и вызывает:

```php
Service_Erp408_Operations::instance()->plan_order(Model_Erp402_Order $order, $user_id = NULL): int
```

Возврат — сколько операций запланировано. Пока модуля нет, метод отдаёт `0`,
и заказ запускается штатно.

## 8. Ограничения текущей версии

- серийные номера и партии продукции не ведутся (план S3/S4);
- плановая себестоимость только хранится, не рассчитывается;
- маршрут операций передаётся цеху, но обратной связи «операция выполнена» нет до `erp408`;
- годный/брак при выпуске не разделяются — выпуск считается годным.
