# erp802_integration — управляемый шлюз обмена

Модуль принимает ограниченные по размеру CSV/JSON-пакеты, ведёт неизменяемый журнал и связывает внешние идентификаторы с UUID PromERP. Первая намеренно узкая граница — номенклатура `erp227`; это основа для последующего адаптера обмена с 1С, а не попытка заменить 1С.

## Контракт `items`

JSON: массив `items`; CSV: заголовки с `;` или `,`. Обязательны `external_id`, `name`; поддержаны `code`, `type` (по умолчанию `component`), `status`, `version`, `attributes` (JSON-объект). Максимум 10 МБ и 10 000 строк.

```json
{"items":[{"external_id":"1c:0000123","code":"MAT-123","name":"Втулка","type":"component","version":"7","attributes":{"unit":"pcs"}}]}
```

- SHA-256 исходного пакета обеспечивает idempotency отдельно для dry-run и реального импорта.
- Каждая строка хранит вход, checksum, статус, reason code, сообщение и внутренний UUID.
- Неизменённая mapped-запись пропускается; изменённая создаёт ревизию `erp227` и обновляет mapping.
- Совпадение `code` без mapping считается `code_conflict`: шлюз не присваивает чужую запись молча.
- Dry-run пишет только журнал и планы строк, но не меняет номенклатуру.
- Повтор разрешён для `failed/partial` и только для eligible error-строк. Дубликат external ID внутри неизменяемого пакета нужно исправить и прислать новым пакетом.
- Завершённый реальный пакет публикует durable outbox-факт `erp802.package.completed`.

## Оператор и API

- `/integration` — загрузка, список и фильтрация пакетов; источник выбирается по коду/названию, внутренние ID не вводятся.
- `/integration/view/<id>` — построчный протокол и контролируемый повтор.
- JSON API: `sources`, `packages`, `package/<id>`, POST `import`, POST `retry/<id>`.
- Миграция обнаруживается общей системой и запускается из `/migrate_pg`.

ACL: `erp802.view`, `erp802.import`, `erp802.retry`.

## MCP / AI boundary

`integration.packages`, `integration.package` и `integration.validate_items` дают наблюдение и dry-run. `integration.import_items` и `integration.retry` являются mutating tools и требуют approval. AI предлагает и объясняет, но не становится источником истины и не разрешает неоднозначную привязку.

## Эксплуатационные свойства

Пакет не оборачивает несколько вызовов registry в одну внешнюю транзакцию: сервис `erp227` сам управляет транзакциями ревизий. Поэтому прогресс журналируется по строкам и безопасно возобновляется. Mapping обновляется только после успешной доменной операции. Для обмена с 1С транспорт должен передать стабильный `external_id` и сохранить checksum/idempotency semantics этого шлюза.
