# Модуль Erp212_Storage

Модуль `Erp212_Storage` предоставляет функциональность для работы с файловым хранилищем в системе Erp212. Он включает в себя API для загрузки, получения метаданных и удаления файлов, а также контроллер для скачивания файлов с проверкой прав доступа. Модуль поддерживает различные бэкенды хранения, такие как локальная файловая система и Amazon S3.

## Структура модуля

Модуль состоит из следующих основных компонентов:

-   **`Controller_Erp212_Api`**: REST API для взаимодействия с файловым хранилищем.
-   **`Controller_Erp212_Download`**: Контроллер для безопасного скачивания файлов.
-   **`Service_Erp212_Storage`**: Основной сервис, инкапсулирующий логику работы с файлами и бэкендами хранения.

## `Controller_Erp212_Api`

Этот контроллер предоставляет RESTful API для управления файлами. Все ответы возвращаются в формате JSON.

### Методы API

#### 1. Загрузка файла

-   **URL**: `/erp212_api/upload`
-   **Метод**: `POST`
-   **Тип контента**: `multipart/form-data`

**Параметры запроса**:

-   `file` (обязательно): Загружаемый файл (передается через `$_FILES`).
-   `is_public` (опционально): `0` или `1`. Если `1`, файл будет публичным. По умолчанию `0`.
-   `backend_id` (опционально): ID бэкенда хранения, если нужно использовать конкретный.

**Пример успешного ответа**:

```json
{
    "success": true,
    "message": "Файл успешно загружен.",
    "data": {
        "id": 123,
        "backend_id": 1,
        "user_id": 456,
        "filename": "my_document.pdf",
        "storage_path": "local/1/2023-10-27/abcdef12345.pdf",
        "mime_type": "application/pdf",
        "file_size": 102400,
        "extension": "pdf",
        "hash": "...",
        "is_public": 0,
        "created_at": "2023-10-27 10:00:00",
        "updated_at": "2023-10-27 10:00:00",
        "deleted_at": null
    },
    "timestamp": 1678886400
}
```

**Пример ответа с ошибкой**:

```json
{
    "success": false,
    "error": "Файл обязателен для загрузки.",
    "code": 400,
    "timestamp": 1678886400
}
```

#### 2. Получение метаданных файла

-   **URL**: `/erp212_api/get_metadata/<id>`
-   **Метод**: `GET`

**Параметры URL**:

-   `id` (обязательно): ID файла.

**Пример успешного ответа**:

```json
{
    "success": true,
    "message": "Успешно",
    "data": {
        "id": 123,
        "backend_id": 1,
        "user_id": 456,
        "filename": "my_document.pdf",
        "storage_path": "local/1/2023-10-27/abcdef12345.pdf",
        "mime_type": "application/pdf",
        "file_size": 102400,
        "extension": "pdf",
        "hash": "...",
        "is_public": 0,
        "created_at": "2023-10-27 10:00:00",
        "updated_at": "2023-10-27 10:00:00",
        "deleted_at": null
    },
    "timestamp": 1678886400
}
```

**Пример ответа с ошибкой**:

```json
{
    "success": false,
    "error": "Файл не найден.",
    "code": 404,
    "timestamp": 1678886400
}
```

#### 3. Удаление файла (мягкое удаление)

-   **URL**: `/erp212_api/delete/<id>`
-   **Метод**: `DELETE`

**Параметры URL**:

-   `id` (обязательно): ID файла.

**Пример успешного ответа**:

```json
{
    "success": true,
    "message": "Файл успешно удален.",
    "data": {
        "id": 123
    },
    "timestamp": 1678886400
}
```

**Пример ответа с ошибкой**:

```json
{
    "success": false,
    "error": "Доступ запрещен. Недостаточно прав для удаления файла.",
    "code": 403,
    "timestamp": 1678886400
}
```

## `Controller_Erp212_Download`

Этот контроллер обрабатывает запросы на скачивание файлов, обеспечивая проверку прав доступа и потоковую передачу данных.

### Методы

#### 1. Скачивание файла по ID

-   **URL**: `/erp212_download/file/<id>`
-   **Метод**: `GET`

**Параметры URL**:

-   `id` (обязательно): ID файла.

Этот метод проверяет права пользователя на скачивание файла через ACL (`erp212_storage.download_file`). Если доступ разрешен, файл передается клиенту.

#### 2. Скачивание файла по временному токену

-   **URL**: `/erp212_download/shared/<token>`
-   **Метод**: `GET`

**Параметры URL**:

-   `token` (обязательно): Временный токен, сгенерированный методом `Service_Erp212_Storage::generateUrl()`.

Этот метод позволяет скачивать файлы по предварительно сгенерированным временным ссылкам. Токен проверяется на валидность и срок действия.

### Обработка ошибок

В случае ошибок (например, файл не найден, доступ запрещен, недействительный токен) контроллер возвращает соответствующий HTTP-статус и JSON-ответ с описанием ошибки.

**Пример ответа с ошибкой**:

```json
{
    "error": "Файл не найден или доступ запрещен"
}
```

## `Service_Erp212_Storage`

Сервис `Service_Erp212_Storage` является центральным компонентом модуля, предоставляющим API для работы с файлами и абстрагирующим логику хранения от конкретных бэкендов.

### Основные методы

-   **`instance()`**: Возвращает синглтон-экземпляр сервиса.
-   **`getFilePath($file_id)`**: Возвращает полный путь к файлу для локального драйвера.
-   **`getFileForDownload($file_id, $user_id = null)`**: Подготавливает данные файла для скачивания, включая проверку прав доступа.
-   **`getFileByToken($token)`**: Подготавливает данные файла для скачивания по временному токену.
-   **`get_files_list(array $params = [])`**: Получает список файлов с фильтрацией и пагинацией.
-   **`get_storage_stats(array $params = [])`**: Получает статистику хранилища (общее количество файлов, общий размер).
-   **`get_active_backends()`**: Возвращает список активных бэкендов.
-   **`get_all_backends()`**: Возвращает список всех бэкендов (включая неактивные).
-   **`set_driver($driver_name)`**: Устанавливает активный бэкенд по имени драйвера.
-   **`saveRaw($content, $filename, array $metadata = [])`**: Сохраняет файл из сырых данных (строки).
-   **`save($file, array $metadata = [])`**: Сохраняет файл из загруженного файла или по пути.
    -   `$file`: Массив `$_FILES['file']` или путь к файлу.
    -   `$metadata`: Массив с дополнительными метаданными (`is_public`, `backend_id`, `user_id`, `custom_path`).
-   **`delete($file_id)`**: Мягкое удаление файла (устанавливает `deleted_at`).
-   **`generateUrl($file_id, $expires_seconds = 3600)`**: Генерирует временный URL для скачивания файла. Для S3 генерирует предподписанный URL, для локального хранилища - URL с временным токеном.
-   **`get_access_logs(array $params = [])`**: Получает логи доступа (на основе таблицы `erp_212_links`).
-   **`validate_mime($mime_type)`**: Проверяет, разрешен ли данный MIME-тип для загрузки.
-   **`get_max_size()`**: Возвращает максимально разрешенный размер файла для загрузки.

### Поддерживаемые бэкенды хранения

Модуль поддерживает следующие драйверы хранения:

-   **`local`**: Локальная файловая система. Файлы хранятся в директории, указанной в конфигурации.
-   **`s3`**: Amazon S3 (или совместимые хранилища). Требует установленного AWS SDK.

### Конфигурация

Конфигурация модуля находится в файле `application/config/erp212_storage.php`.

Пример конфигурации:

```php
<?php defined('SYSPATH') or die('No direct script access.');

return array(
    'allowed_mime_types' => array(
        'image/jpeg',
        'image/png',
        'application/pdf',
        'application/msword',
        'application/vnd.openxmlformats-officedocument.wordprocessingml.document',
        // ... другие разрешенные MIME-типы
    ),
    'upload_max_size' => 10485760, // 10 MB
    'local_storage_paths' => array(
        'default' => APPPATH . 'storage/files', // Путь для локального хранилища по умолчанию
    ),
    // ... другие настройки
);
```

Бэкенды хранения настраиваются через базу данных (таблица `erp_212_backends`).

### События

Модуль генерирует следующие события:

-   `erp212_storage.uploaded`: После успешной загрузки файла. Передает метаданные файла.
-   `erp212_storage.metadata_read`: После успешного получения метаданных файла. Передает метаданные файла.
-   `erp212_storage.deleted`: После успешного мягкого удаления файла. Передает метаданные удаленного файла.
-   `erp212_storage.file_downloaded`: После успешного скачивания файла по ID. Передает `file_id` и `user_id`.
-   `erp212_storage.shared_file_downloaded`: После успешного скачивания файла по токену. Передает `file_id` и `token`.

### Права доступа (ACL)

Модуль использует систему ACL для проверки прав доступа к файлам:

-   `erp212_storage.upload`: Разрешение на загрузку файлов.
-   `erp212_storage.read`: Разрешение на чтение метаданных файла.
-   `erp212_storage.delete`: Разрешение на удаление файла.
-   `erp212_storage.download_file`: Разрешение на скачивание файла по ID.
-   `erp212_storage.download_shared_file`: Разрешение на скачивание файла по временному токену.

Проверки прав выполняются в контроллерах и сервисе.
