# Архитектура файлового хранилища: Мысли и рекомендации

## 1. Хранение по папкам (по 1000 файлов) vs Даты

Идея уйти от дат к индексированным папкам (например, `000/`, `001/`, `002/`) — это классический подход для высоконагруженных систем.

**Почему это хорошо:**
*   **Ограничения файловых систем:** В старых FS (типа ext3) производительность падает, если в одной директории больше 10-30 тысяч файлов. Даже в современных FS (ext4, XFS) листинг директории с миллионом файлов будет "тормозить" терминал и скрипты.
*   **Равномерность:** Вы четко контролируете количество объектов в одной папке.

**Как это реализовать технически:**
Вместо `date('Y-m-d')` в методе `_generate_storage_path` можно использовать ID следующей записи в БД:
`floor($next_id / 1000)`.

## 2. Префиксы модулей и очистка

Использование префиксов — критически важная штука для поддержки. Если через год вам скажут "удалить все временные превью из модуля `catalog`, но не трогать сканы из `accounting`", без префиксов это будет мучением.

**Как лучше поступить:**
Не ограничивайтесь только префиксом в имени файла. Лучше внедрить понятие **"Namespace" (Пространство имен)** или **"Bucket"** на уровне логики.

### Рекомендуемая структура пути:
`{module_prefix}/{folder_index}/{filename}`

**Почему это удобно:**
1.  **Очистка:** Вы можете просто сделать `rm -rf storage/temp_module/*`.
2.  **Квоты:** Можно быстро посчитать `du -sh storage/module_name`, чтобы понять, кто "съел" всё место.
3.  **Безопасность:** Можно на уровне Nginx/Apache запретить доступ к папке конкретного модуля.

## 3. Изменения в коде (Service_Erp212_Storage)

Чтобы реализовать ваши идеи, нужно модифицировать метод `save` и `_generate_storage_path`.

### Предложение по реализации:

1.  **В метод `save($file, array $metadata = [])`** добавить опциональный ключ `module`.
2.  **Обновить генерацию пути:**


### Как использовать в фасаде `Storage`:

```php
// Для модуля LIMS, который можно чистить
Storage::upload($_FILES['report'], 'lims_temp');

// Для модуля Бухгалтерия, который нельзя трогать
Storage::upload($_FILES['invoice'], 'accounting_permanent');
```

## Итоговый вердикт:
1.  **Папки по 1000:** Делайте, если хотите идеальный порядок. Если решите делать — используйте `floor($file_id / 1000)`, но сначала `INSERT` в БД, а потом `UPDATE` пути после загрузки.
2.  **Префиксы:** **Обязательно добавляйте.** Это спасет проект при масштабировании. Добавьте в таблицу `erp_212_files` колонку `module_prefix` (string) для быстрой фильтрации в БД без парсинга строк.

структура пути должна быть такой:
`{module_prefix}/{folder_index}/{filename}`
