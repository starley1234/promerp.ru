# Модуль LLM для Kohana

Универсальный сервис для работы с Large Language Models (OpenAI, OpenRouter, Local LLM и др.) через единый интерфейс.

## Основные возможности

*   **Единый синтаксис**: Работа с разными провайдерами через статический прокси-класс `Llm`.
*   **Мультимодальность**: Поддержка анализа изображений (Vision).
*   **Структурированные данные**: Извлечение JSON по схеме.
*   **Интеграция с ORM**: Автоматическая конвертация моделей Kohana в текстовое представление для анализа.
*   **Tool Calling**: Поддержка вызова PHP-функций самой моделью.
*   **MCP (Model Context Protocol)**: Поддержка серверных инструментов через Toolforge.
*   **Шаблонизация**: Использование именованных промптов с переменными.
*   **Логирование**: Автоматическое сохранение всех запросов, ответов и статистики токенов в БД.

## Примеры использования

### Базовые запросы
```php
// Простой текстовый ответ (модель по умолчанию)
$text = Llm::ask("Напиши текст для рассылки");

// Смена модели на лету (провайдер::модель)
$answer = Llm::model('openrouter::google/gemini-1.5-pro')->ask("Проанализируй код");

// Запрос с системным промптом
$pro = Llm::system("Ты юрист")->ask("Проверь договор на риски");
```

### Работа с изображениями (Vision)
```php
// Путь к файлу, URL или base64
$desc = Llm::model('openai::gpt-4o')->vision('path/to/invoice.jpg', 'Сумма счета?');

// Анализ нескольких картинок сразу
$diff = Llm::vision(['img1.png', 'img2.png'], 'В чем разница между товарами?');
```

### Извлечение данных и анализ ORM
```php
// Получение структурированного JSON (возвращает массив)
$data = Llm::extract($text, ['amount', 'vendor', 'date']);
echo $data['amount'];

// Анализ объекта ORM (авто-конвертация в JSON внутри)
$order = ORM::factory('Order', 1);
$summary = Llm::analyze($order, "Найди подозрительные несостыковки в заказе");
```

### Использование инструментов (Tools / MCP)

**Локальные PHP-функции:**
```php
$res = Llm::tools([
    'get_stock' => function($id) { 
        return Inventory::where('product_id', '=', $id)->find()->qty; 
    }
])->ask("Сколько товара артикула 105 на складе?");
```

**Внешние MCP-инструменты (через Toolforge):**
```php
// Подключение серверных инструментов по их именам
$res = Llm::model('local_lms::google/gemma-4-e4b')
        ->system("Используй инструменты")
		->mcp([
                "type" => "mcp",
                "server_label" => "memory",
                "server_url" => "https://memory_tool.ru/sse",
                "allowed_tools" => ["ai_remember", "ai_recall"]
            ],)
    ->ask("Запомни факты");
```

### Промпты и шаблоны
Шаблоны хранятся в конфигурации `llm_prompts.php`.
```php
// Вызов шаблона 'invoice_check' с передачей переменных
$review = Llm::prompt('invoice_check', ['invoice' => $data])->ask();

// Комбинирование модели и шаблона
$html = Llm::model('anthropic::claude-3')->prompt('email_notify', ['user' => $user])->ask();
```

## Архитектура

1.  **`Llm`**: Статический прокси для быстрого доступа.
2.  **`Llm_Factory`**: Инициализирует сервис на основе конфигурации.
3.  **`Llm_Service`**: Основная логика цепочек вызовов, выбора провайдера, обработки инструментов и логирования.
4.  **`Interface_LlmProvider`**: Интерфейс для реализации новых провайдеров.
5.  **Провайдеры**: 
    *   `OpenAICompatible`: Для OpenAI, OpenRouter, DeepSeek и др.
    *   `Toolforge`: Специализированный провайдер с поддержкой MCP и серверного исполнения инструментов.

## Логирование
Все запросы сохраняются в таблицу `llm_requests` (через модель `Llm_Request`), включая:
*   Провайдер и модель.
*   Входные сообщения и параметры.
*   Полный ответ API.
*   Количество токенов (prompt, completion, total).
*   Длительность выполнения в мс.
*   ID сессии пользователя.
