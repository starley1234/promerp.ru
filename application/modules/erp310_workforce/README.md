# erp310_workforce — сотрудники и организационная структура

Модуль разделяет три понятия, которые нельзя хранить одной записью:

* **пользователь** (`erp100`) — учётная запись, роли и вход;
* **сотрудник** (`erp310`) — человек и кадровый статус;
* **назначение** (`erp310`) — подразделение, должность, руководитель, ставка и период.

Это источник организационного контекста для прав доступа, цеха, табеля и
себестоимости. `erp230_mdm` не используется как кадровая база: MDM принимает и
согласует внешние мастер-данные, а erp310 владеет операционными правилами труда.

## Реализовано

| Раздел | Адрес / контракт |
|---|---|
| Сводка | `GET /workforce` |
| Сотрудники | `GET /workforce/employees` |
| Карточка и назначение | `GET /workforce/employees/view/<id>`, `edit/<id>`, `POST save` |
| История и увольнение | история назначений в карточке, `POST /workforce/employees/dismiss/<id>` |
| Подразделения | `GET /workforce/departments`, `POST /workforce/departments/save` |
| Должности | `GET /workforce/positions`, создание и безопасная архивация |
| JSON API | employees, employee, departments, positions, history |

Таблицы: `erp_310_departments`, `erp_310_positions`, `erp_310_employees`,
`erp_310_assignments`. Текущее основное назначение одно, прошлые назначения
закрываются датой и сохраняются.

## Права

* `erp310.view` — чтение сотрудников и структуры;
* `erp310.manage` — изменение кадрового справочника;
* `erp310.*` — полный доступ администратора.

## MCP / AI

Восемь инструментов: поиск и карточка сотрудника, оргструктура, должности,
штат/вакансии, сохранение штатного плана, сохранение сотрудника и увольнение. Изменение персональных данных и увольнение требуют
подтверждения человека (`approval`); агент вызывает тот же сервис, что UI.

Форма сотрудника использует общий `smart_reference` для руководителя и учётной
записи: человек ищет по ФИО/табельному номеру или логину/e-mail и не вводит ID.
ACL-защищённый endpoint `/workforce/api/reference` возвращает единый контракт
`{items: [{id, label, context}]}`, а сервис повторно проверяет ссылку при save.

## События

`erp310.employee.created`, `erp310.employee.updated`, `erp310.employee.dismissed`,
`erp310.department.*`, `erp310.position.*`, `erp310.staff_unit.*`.

Штатное расписание (`erp_310_staff_units`) хранит план FTE с периодом действия;
занятые ставки вычисляются из текущих назначений, вакансии — как разница плана
и факта. Архивирование закрывает период, а не удаляет кадровое решение.

## Границы и следующие шаги

В следующем срезе: штатные единицы и вакансии, область доступа пользователя
(подразделение/склад/участок), MCP-инструменты и синхронизация со сменами erp408.
Табель, сдельные наряды и расчёт оплаты относятся к будущему `erp411_worktime`.
