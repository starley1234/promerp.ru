# Core Registry Module (erp227)

Универсальный реестр объектов ERP системы. Модуль предоставляет централизованное хранилище для любых сущностей (оборудование, ТМЦ, услуги, сотрудники) с поддержкой версионности, иерархии и гибридного поиска.

## Основные возможности

*   **Универсальная структура**: Хранение объектов различных типов в единой таблице с использованием JSONB для гибких атрибутов.
*   **Версионность (Ревизии)**: Автоматическое сохранение истории изменений объекта. Каждое обновление создает новую ревизию, помечая предыдущую как архивную.
*   **Иерархия (Ltree)**: Поддержка древовидных структур (например, дерево оборудования или структура подразделений) на уровне базы данных PostgreSQL.
*   **Связи (Graph-like)**: Возможность устанавливать типизированные связи между любыми объектами (состав изделия, аналоги, зависимости) с указанием количества и единиц измерения.
*   **Гибридный поиск**:
    *   Полнотекстовый поиск (TSVector) с учетом весов полей (код, имя, атрибуты).
    *   Семантический поиск (Vector) с использованием эмбеддингов (pgvector) и LLM.
*   **Валидация**: Проверка атрибутов объекта на соответствие JSON-схеме, заданной в типе объекта.
*   **События и Телеметрия**: Секционированная таблица событий для хранения истории изменений, логов датчиков и действий пользователей.

## Структура базы данных

*   `erp_227_units`: Справочник единиц измерения.
*   `erp_227_object_types`: Шаблоны (дискриминаторы) объектов, содержащие JSON-схемы и настройки UI.
*   `erp_227_objects`: Главный реестр. Содержит код, наименование, путь (ltree), атрибуты и флаги актуальности ревизии.
*   `erp_227_object_links`: Таблица связей между объектами.
*   `erp_227_events`: Журнал событий, секционированный по годам.
*   `erp_227_embeddings`: Векторные представления объектов для семантического поиска.

## Использование (API)

Для работы с реестром используется глобальный прокси-класс `Registry`.

### Работа с объектами

```php
// Создание объекта
$object = Registry::create_object([
    'type' => 'equipment',
    'code' => 'PUMP-001',
    'name' => 'Насос центробежный',
    'attributes' => ['power' => 15, 'pressure' => 10]
]);

// Получение объекта
$pump = Registry::get('PUMP-001', 'equipment');

// Создание новой ревизии (обновление)
Registry::update_object($pump->id, [
    'name' => 'Насос центробежный (модернизированный)',
    'attributes' => ['power' => 18, 'pressure' => 10]
]);
```

### Иерархия и связи

```php
// Установка родителя
Registry::update_object($child_id, ['parent_id' => $parent_id]);

// Получение пути (хлебные крошки)
$path = Registry::get_path($object_id);

// Создание связи между объектами (например, запчасть к оборудованию)
Registry::link($equipment_id, $part_id, 'spare_part', 2, 'pcs');
```

### Поиск

```php
// Гибридный поиск (текст + семантика)
$results = Registry::search('насос для воды', ['status' => 'active']);

// Поиск по конкретным атрибутам в JSONB
$items = Registry::find_by_attributes(['power' => 18]);
```

## Требования

*   PostgreSQL 15+
*   Расширения: `ltree`, `vector`, `pgcrypto`
*   Модуль `Llm` (для работы векторного поиска)
