# erp404_documents — документы и печать

Модуль отвечает на вопрос «что мы отдали на бумагу и чем это подтверждается»:
шаблоны печатных форм, выпуск документов, журнал печати, архив.

- **ID:** 404 (диапазон 400–599, Operations)
- **Таблицы:** `erp_404_templates`, `erp_404_documents`, `erp_404_prints`, последовательность `erp_404_document_number_seq`
- **Экраны:** `/documents`, `/documents/view/<id>`, `/documents/edit/<id>`, `/documents/templates`, `/documents/print/<id>`
- **JSON API:** `/documents/api/<action>(/<id>)`
- **MCP:** `documents.*` (13 инструментов), объявления — в `mcp.php` модуля

## Зачем модуль

Раньше каждая бумага рисовалась в своём модуле: заказ поставщику — в закупках,
паспорт партии — в качестве, и «какой шаблон использовали в прошлый раз» не
отвечал никто. Модуль держит документ как сущность:

1. **Шаблон** (`erp_404_templates`) — тело формы на HTML с подстановками
   `{{ref.number}}`, `{{document.title}}`, `{{meta.date}}` и блоками списков
   `{{#rows ref.lines}}…{{/rows}}` (внутри доступен `{{index}}`).
2. **Документ** (`erp_404_documents`) — номер `ДК-ГГГГ-НННННН`, ссылка на объект
   (`ref_type` + `ref_id`), состояние, снимок HTML и версия шаблона.
3. **Печать** (`erp_404_prints`) — событие: кто, когда, сколько копий.

Ключевое свойство: **выпущенный документ не переписывается**. При выпуске
фиксируется снимок (`rendered`) и версия шаблона; правка формы после этого
меняет только будущие документы. Именно поэтому бумага не «плывёт» задним числом,
а журнал печати остаётся доказательством.

## Путь документа

```
create → draft ──issue──→ issued ──print──→ printed ──archive──→ archived
   │                        │                  │
   └────────cancel──────────┴──────────────────┘        (номер остаётся занятым)
```

- `draft` — правится свободно, снимка нет, печатать нельзя (`not_issued`);
- `issued` — данные собраны у владельца, подстановки раскрыты, снимок записан;
- `printed` — есть хотя бы одна запись в журнале печати;
- `archived` / `cancelled` — дальше только чтение (отмена требует причины).

## Права

| Право           | Кому                | Что разрешает |
|-----------------|---------------------|---------------|
| `erp404.view`   | admin, manager, accountant, worker | документы, шаблоны, журнал печати, предпросмотр |
| `erp404.print`  | admin, manager, accountant, worker | черновик, выпуск, печать, архив, отмена |
| `erp404.manage` | admin, manager       | шаблоны форм (правка тела поднимает версию) |

В MCP изменяющие инструменты идут через подтверждение человека. Для сменного
задания агент использует шаблон `SHIFT-ASSIGNMENT`, `ref_type=erp408_shift_day`
и понятный `ref_id=ГГГГ-ММ-ДД`: сначала `documents.preview`, затем предлагает
`documents.issue`, но не утверждает и не печатает документ автономно.
`documents.cancel` дополнительно помечен destructive: номер занят, а бумага с
ним могла уже уехать контрагенту.

## Данные подстановок

Печатная форма не ходит по таблицам соседей — за данные отвечает
`Service_Erp404_Sources`: он зовёт владельца и отдаёт «печатный» набор (числа уже
в виде `1 250,000`, состояния — подписями).

| `ref_type`            | Источник | Что даёт |
|-----------------------|----------|----------|
| `erp403_order`        | erp403   | заказ поставщику: поставщик, склад, дата, строки с количеством, ценой и суммой |
| `erp403_receipt`      | erp403   | приёмка: поставщик, склад, строки с решением входного контроля |
| `erp402_order`        | erp402 + erp408 | производственный заказ: изделие, количество, состав (`materials`) и маршрут (`route`) |
| `erp405_inspection`   | erp405   | паспорт партии: вид контроля, итог, решение, несоответствия с причиной |
| `erp408_operation`    | erp408   | операция цеха: заказ, центр, план/факт, состояние |
| `erp408_shift_day`    | erp408   | отдельное сменное задание по ISO-дате: центры, смены, заказы, операции и часы |
| `` (пусто)            | вызывающий | универсальный шаблон: данные передаёт форма или агент |

Ошибки данных честные и машинные (`Exception_Erp404_Documents::reason()`):
`dependency` — модуль-источник недоступен, `ref_not_found` — объекта нет,
`unknown_ref` — тип объекта не поддержан, `unknown_placeholder` — в шаблоне
подстановка с опечаткой. Ни один из этих случаев не «печатает пустое место».

## Проверка перед выпуском

`documents.preview` / кнопка на карточке собирает данные и раскрывает шаблон, не
сохраняя ничего: видно список проблем («нет заказа-источника», «подстановка
`{{ref.такого_поля}}` неизвестна») и готовый HTML. Выпуск после этого — один шаг.

## Печать

Снимок отдаётся страницей `/documents/print/<id>` — чистая вёрстка без макета
системы, с кнопкой «Печать» и `@media print`. Отметка о печати ставится на
карточке (или вызовом `documents.print`) и попадает в журнал: браузер не ведёт
учёт бумаги, это делает модуль.

## Связи

- `erp212_file_storage` — скан-копии (своей таблицы вложений у модуля нет: файлы
  живут в хранилище, документ ссылается на объект);
- `erp119_audit` — журнал действий: `document_created`, `document_issued`,
  `document_printed`, `document_archived`, `document_cancelled`, `template_*`;
- события `erp404.document.*` и `erp404.template.saved` — для подписчиков;
- `erp403`, `erp402`, `erp405`, `erp408` — источники данных подстановок.
