# Технологические карты (erp228_tech_cards)

**ID модуля:** 228
**Слаг:** `tech_cards`
**Слой:** Platform / data (диапазон 200–299)
**Префикс таблиц:** `erp_228_*`
**Статус:** портирован на PostgreSQL, включён, 19 тестов

---

## 1. Назначение

Модуль превращает исходник изделия (параметрическая модель, код OpenSCAD или
описание) в **техпроцесс**: последовательность операций с нормами времени,
стоимостью и технологическими параметрами. Это «мост» между конструкцией
изделия и производством: склад (`erp401`) знает материалы, контрагенты
(`erp301`) — исполнителей, а что именно и в каком порядке делать — знает техкарта.

Генерация работает в двух режимах:

| Режим | Когда используется | Что даёт |
| :--- | :--- | :--- |
| LLM (`llm.enabled = TRUE`) | настроен модуль `llm` | техпроцесс по исходному коду изделия, ответ модели разбирается в операции |
| Офлайн-шаблон (по умолчанию) | ключа модели нет или модель недоступна | типовой техпроцесс по типу производства, с нормами и стоимостью |

Модуль **не владеет** номенклатурой (реестр `erp227`), материалами и остатками
(`erp401`), файлами (`erp212`). Он описывает, *как изготовить*, а не *из чего и сколько есть*.

## 2. Возможности

| Раздел | Что умеет |
| :--- | :--- |
| Сводка `/tech_cards` | карты по статусам и типам производства, число версий и операций, суммарная стоимость |
| Список `/tech_cards/list` | поиск по названию и типу, фильтры по статусу и производству, постраничный вывод |
| Карточка `/tech_cards/view/<id>` | исходный код, описание техпроцесса, операции с нормами времени и стоимостью, история версий |
| Форма `/tech_cards/editor(/<id>)` | создание и правка карты: название, тип производства, тип объекта, исходный код, параметры (JSON) |
| Генерация | кнопка «Сгенерировать техпроцесс»: LLM или офлайн-шаблон, результат — новая версия документа |
| API `/tech_cards/api/*` | `status`, `data`, `search`, `suggest`, `stats`, `generate` — JSON для других модулей |
| Виджеты `/tech_cards/widget/*` | `status_badge` (бейдж состояния) и `operations_list` (список операций) для вставки в чужие страницы |

## 3. Данные

```
erp_228_tech_cards      1 --- n  erp_228_tech_documents  (версии техпроцесса, одна актуальная)
erp_228_tech_documents  1 --- n  erp_228_tech_operations (операции: время, стоимость, параметры jsonb)
```

| Таблица | Назначение | Ключевые колонки |
| :--- | :--- | :--- |
| `erp_228_tech_cards` | карта: что изготовить и в каком состоянии | `uuid`, `title`, `source_code`, `production_type`, `target_type`/`target_id`, `input_params` (jsonb), `status`, `search_text` |
| `erp_228_tech_documents` | версия техпроцесса от одной генерации | `tech_card_id`, `is_actual`, `content_markdown`, `structured_data` (jsonb), `llm_model`, `tokens_total`, `gen_time_ms` |
| `erp_228_tech_operations` | шаг техпроцесса | `document_id`, `sort_order`, `op_name`, `op_description`, `duration_sec`, `cost_amount`, `params` (jsonb) |

Актуальная версия у карты **ровно одна** — это гарантирует частичный уникальный
индекс `erp_228_tech_documents_actual_uniq (tech_card_id) WHERE is_actual = 1`,
а не только код приложения.

Миграции: `migrations_pg/pgMigration_001_Erp228_TechCards_CreateTables.php`,
`migrations_pg/pgMigration_002_Erp228_TechCards_Seed.php` (демо-карты).

## 4. Маршруты и права

| Маршрут | Действие | Право |
| :--- | :--- | :--- |
| `/tech_cards`, `/tech_cards/list`, `/tech_cards/view/<id>` | сводка, список, карточка | `erp228.view` |
| `/tech_cards/editor(/<id>)`, `/tech_cards/save(/<id>)` | создание и правка карты | `erp228.manage` |
| `/tech_cards/generate` (POST) | запуск генерации техпроцесса | `erp228.manage` |
| `/tech_cards/delete` (POST) | карта в архив | `erp228.delete` |
| `/tech_cards/api/<action>(/<id>)` | JSON API (`stats` по умолчанию) | `erp228.view` / `erp228.manage` |
| `/tech_cards/widget/<action>(/<id>)` | HMVC-виджеты | `erp228.view` |

Частные маршруты объявлены до общего `tech_cards(/<action>(/<id>))`: параметр
`<action>` в середине пути превращается в метод `action_<значение>`, поэтому
составные адреса описываются отдельными правилами с явным действием в `defaults()`.

## 5. Сервисы

| Класс | Ответственность |
| :--- | :--- |
| `Service_Erp228_TechCards` | жизненный цикл карты: создание, правка, статусы, поиск, статистика, версии документов, публикация событий |
| `Service_Erp228_Parser` | разбор ответа LLM (JSON, ```фенс, markdown) в операции; офлайн-шаблоны по типам производства; сборка промпта |
| `Service_Erp228_LlmProcessor` | оркестрация генерации: статусы, вызов модели через фасад `Llm`, откат в офлайн-шаблон, сохранение версии |

Контроллеры тонкие: вся логика — в сервисах, данные меняются только через них.

### События

`erp228.card.created`, `erp228.card.updated`, `erp228.card.deleted`,
`erp228.card.status`, `erp228.card.document` — подписчики (уведомления, аудит,
аналитика) подключаются без правки модуля.

## 6. Настройка

`config/erp228_tech_cards.php`:

```php
'llm' => array(
    'enabled' => FALSE,   // TRUE — реальный вызов модели
    'model'   => NULL,    // 'провайдер::модель' как в модуле llm
    'strict'  => FALSE,   // TRUE — при сбое модели карта получает статус «Ошибка»
),
'items_per_page' => 20,
```

Ключи и провайдеры моделей модуль не хранит: это ответственность `llm`
(`/llm_admin`). Ограничения исходного кода — `limits.max_source_code_size`.
