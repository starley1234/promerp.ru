# Умное заполнение форм и LLM-помощник

Дата: 2026-09-17. Цель: перестать заставлять пользователя знать внутренние ID и
добавить AI там, где он уменьшает ручной ввод, не отдавая ему право незаметно
менять учётные данные.

## 1. Правило интерфейса: ID никогда не вводится человеком

Поле `warehouse_id`, `item_id`, `employee_id`, `supplier_id` и подобные — это
контракт сервера, а не элемент интерфейса. Пользователь видит smart reference:

* строку поиска по коду, названию, номеру, ИНН, ФИО;
* список top-N с контекстом и причиной совпадения;
* выбранную карточку-чип с возможностью очистить/открыть;
* скрытый ID, выставляемый только компонентом;
* создание нового объекта отдельным разрешённым действием.

`<select>` допустим только для короткого стабильного списка до ~30 элементов.
Datalist не подходит: не хранит надёжно ID, беден для клавиатуры и контекста.

## 2. Общий компонент SmartReference

Предлагаемые файлы:

* `application/views/components/smart_reference.php`;
* `public_html/assets/js/smart-reference.js`;
* `Controller_Api_Reference` или endpoint владельца сущности;
* `Service_Reference_Registry` — реестр провайдеров без чтения чужих таблиц.

HTML-контракт: `data-reference="registry.item"`, `data-url`, `data-value`,
`data-label`, `data-context`. Компонент реализует ARIA combobox/listbox,
стрелки, Enter/Escape, debounce, AbortController, состояния loading/empty/error.

Единый JSON:

```json
{
  "items": [
    {"id": 42, "label": "MAT-PLA-BLK · PLA чёрный", "subtitle": "кг · материал", "meta": {"available": 18.4}, "score": 0.97}
  ],
  "next": null
}
```

Endpoint обязан применять ACL и область доступа до поиска. Клиент не является
границей безопасности. Сохранение повторно валидирует существование и
доступность ID.

## 3. Реестр провайдеров

Каждый модуль-владелец объявляет поиск через сервис:

* `registry.item` → erp227;
* `warehouse` → erp401;
* `counterparty.supplier` → erp301;
* `workforce.employee|department|position` → erp310;
* `production.order` → erp402;
* `shopfloor.center` → erp408.

Никакого центрального SQL JOIN по всем таблицам. Общий компонент знает только
контракт, а provider вызывает публичный сервис владельца.

## 4. Роль LLM

LLM — второй слой над обычным поиском, а не замена combobox. Кнопка «Заполнить с
помощником» принимает текст, документ или фото и возвращает **draft patch**:

```json
{
  "fields": {
    "supplier_id": {"value": 17, "label": "ООО Ромашка", "confidence": 0.93, "source": "ИНН 770…"},
    "target_date": {"value": "2026-10-12", "confidence": 0.71, "source": "поставка до 12 октября"}
  },
  "warnings": ["Валюта в документе не указана"]
}
```

Пользователь видит diff: текущее → предложенное, confidence, источник и ошибки.
Можно принять поле, секцию или всё безопасное. Сохранение проходит обычный
сервис и те же проверки, что ручная форма.

## 5. Приоритетные сценарии

1. BOM/накладная/заказ из PDF, Excel или фото → staging rows + smart matching.
2. Техкарта: черновик операций и норм из описания изделия.
3. Закупка: поставщик, позиции, сроки и цены из входящего предложения.
4. Качество: классификация свободного описания дефекта с предложением кода.
5. Сотрудники: импорт штатного списка и предложения по сопоставлению учётных
   записей; персональные данные не отправлять внешнему провайдеру без политики.

## 6. MCP и безопасность

LLM-помощник вызывает MCP tools модулей, а не пишет в БД. Разделить инструменты:

* `*.search/get/validate` — read-only;
* `*.draft/preview` — создаёт staging draft, но не боевой документ;
* `*.apply` — mutating, идемпотентность обязательна;
* `*.approve/dismiss/delete/post` — approval человеком.

Защита: минимальные scopes, маскирование ПДн и коммерческих цен, лимиты размера,
изоляция текста документа от системных инструкций, журнал prompt/model/result,
срок хранения, запрет обучения провайдера на данных заказчика. Prompt injection
из загруженного документа считается недоверенным вводом.

## 7. План внедрения

### UI-1
Сделать общий smart reference и применить в erp310 (пользователь/руководитель),
erp402 (изделие/склады/контрагент), erp403 (поставщик/номенклатура). Метрика:
ручных полей `*_id` в UI — 0.

### AI-1
Общий формат draft patch, журнал AI-предложений, preview/diff и ручное принятие.
Первый сценарий — импорт EBOM/MBOM, потому что там максимальная экономия ввода и
результат легко проверить структурными правилами.

### AI-2
Обратная связь «принято/исправлено/отклонено», локальный словарь сопоставлений
без дообучения модели, пакетная обработка и фоновые задачи с retry.

## 8. Антипаттерны

* текстовое поле «Введите ID»;
* LLM сразу вызывает save/post/approve;
* автоподстановка первого fuzzy-совпадения;
* скрытие confidence и источника;
* отдельный несовместимый autocomplete в каждом модуле;
* отправка всей базы или ПДн внешней модели ради одной подсказки.
