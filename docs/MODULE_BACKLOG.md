# Какие модули делать: очередь разработки PromERP

> Документ отвечает на вопрос «какие модули нужно сделать и в каком порядке».
> Основание — цель платформы: **готовое производственное решение** (изделие → техкарта →
> производственный заказ → материалы → выпуск → склад → закупки → себестоимость → аналитика).
> Сроки — оценка трудозатрат одного разработчика с ИИ-ассистентом, в рабочих днях.

## 0. Что уже есть (чтобы не делать дважды)

| Не подключены, оставлены намеренно | `yandexauth`, `PostgreSQL_PDO` | решение 2026-10-02: не удалять, Яндекс-авторизация вернётся позже |

Ключевой вывод: **фундамент уже есть** (реестр, MDM, шина событий, файлы, уведомления, склад).
Не хватает производственного ядра и коммерческого контура.

## 1. P0 — то, без чего производственный контур не замкнётся

### 1.1 `erp301_counterparty` — Контрагенты, договоры, реквизиты  ⟵ *сделано (модуль целиком)*

| | |
| :--- | :--- |
| Зачем | Без контрагентов нельзя ни закупать, ни отгружать, ни печатать документы. Сейчас их нет вообще: закупки и сбыт упираются в ручной ввод названий. |

Почему именно так:

1. **Сначала данные и нормы** (`erp301`, `erp228`) — на них опираются все расчёты; без них
   производственный заказ считать нечем.
2. **Затем ядро** (`erp402`) — оно даёт первый демонстрируемый результат заказчику
   (заказ → списание → выпуск) и сразу проверяет склад, реестр и шину событий в деле.
3. **Затем факт из цеха** (`erp408`) — без него себестоимость и план остаются теоретическими.
4. **Планирование и закупки** (`erp407`, `erp403`) — замыкают цикл «нужно → купить → получить».
5. **Деньги и документы** (`erp409`, `erp404`, `erp406`) — делают систему пригодной для
   реальной эксплуатации и для разговора с бухгалтерией и службой главного механика.
6. **Отгрузка, аналитика, интеграции** — расширяют контур, когда ядро уже работает.

Сквозные требования к каждому модулю — в `docs/DEPLOY_AND_ROADMAP.md` (Definition of Done),
инструменты быстрой проверки — `make check` и `docs/DEVELOPMENT.md`.
