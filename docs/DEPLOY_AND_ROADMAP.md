## 2. Как развернуть

### 2.1 Продакшен (целевая схема)

```
nginx (TLS, статика)  →  php-fpm 8.4 (N воркеров)  →  PostgreSQL 16 (+pgvector)
                              │
                              ├─ деплой: bin/console db:migrate  (только CLI)
                              └─ cron:   bin/console erp217:process / erp227:indexing
                                         bin/console erp212:storage:cleanup
```

Чек-лист перед первым релизом:

1. `KOHANA_ENV=PRODUCTION`, `STRICT_DEPRECATIONS=0` (депрекейшены — в лог, не в 500).
2. `COOKIE_SALT`, `AUTH_HASH_KEY` — сгенерировать (`bash bin/setup.sh`), хранить в секретах.
3. `TRUSTED_HOSTS` — только реальные домены; `MIGRATIONS_TOKEN` — либо пусто (тогда HTTP-миграции
   запрещены вне DEVELOPMENT), либо длинный случайный токен.
4. `composer install --no-dev` — без него не работают экспорт/печать/почта/MQTT-модули
   (guzzle, monolog, carbon, dompdf, PhpWord, PhpSpreadsheet, phpdotenv, php-mqtt, php-amqplib, swiftmailer).
5. Каталоги `application/{cache,logs,sessions}`, `public_html/uploads` — на запись;
   web-root = только `public_html`, `application/` и `system/` вне document root
   (в `docker/nginx/default.conf` это уже закрыто).
6. Бэкапы PostgreSQL (`pg_dump`/WAL) + мониторинг (slow query, ошибки в `application/logs`).
7. Ротация логов, лимиты php-fpm по памяти, `opcache.validate_timestamps=0` после деплоя.

### 2.2 Dev-сервер (одна команда, без nginx)

```bash
bash bin/setup.sh
bin/console db:migrate
bin/console auth:user --email=admin@promerp.local --password=admin12345 --username=admin --admin=1
bin/serve                    # http://0.0.0.0:8080 (роутер bin/router.php)
make check                   # линт + аудит + тесты + прогон маршрутов + диагностика
```

### 2.3 Развёртывание «с нуля» (нет ни PHP, ни PostgreSQL, нет sudo)

```bash
bash bin/restore-env.sh            # PG → PHP → конфиги → миграции → админ → проверка кода
bash bin/restore-env.sh --pg-only  # только база
bash bin/restore-env.sh --app-only # только конфиги/миграции
```

Скрипт рассчитан на ограниченные окружения: PostgreSQL берётся переносимыми бинарями
из PyPI (`pgserver`), расширения при необходимости собираются `bin/pg-contrib.sh`,
PHP — из `PATH`/`PHP_BIN`, из локальных сборок проекта или из npm-пакета с готовым PHP 8.4.
Таблица отладки — `docs/DEVELOPMENT.md`, раздел 8.

### 2.4 Docker и CI

* `docker-compose.yml` + `docker/` (nginx, php-fpm 8.4, pgvector/pg16, Adminer, Mailpit) —
  восстановлены как документированный путь для команды. **В песочнице Arena Docker
  недоступен (реестры образов закрыты), поэтому этот путь не проверен** — при первом
  запуске у себя проверьте `docker compose up -d && docker compose exec app php public_html/index.php --task=dev:doctor`.
* `.github/workflows/ci.yml` — запускает `make check`, миграции и вход на PHP 8.2/8.4
  с PostgreSQL 16 (pgvector). Требуется проверить на GitHub Actions.
* `phpunit.xml.dist` — конфигурация PHPUnit для тех, у кого есть composer;
  без него тесты идут встроенным раннером `bin/test`.
